# Real-issue North-Star — crew on #548 (/help rollups) — 2026-06-27

The first end-to-end run of the autonomous crew on a **real GitHub issue** after the
#672 trilogy (#677 honesty / #678 delivery / #679 plan-shape) and the locked gate
(#675) landed. #548 is the canonical North-Star: runs A–E (the original #672 study)
implemented it **0 of N times while appearing to complete**. This is the payoff test —
and the result is valuable precisely because it is **honest**, and because it localized
the next bottleneck to a *deterministic bug we can name and fix*, not a vague "the model
isn't good enough."

> Security invariant: model identities only; hosts/endpoints in local config.

## Setup

- **Issue #548 — "/help rollups."** At the top-level `/help`, roll the verbose `/dgx`
  subcommand block (status, models, ps, warm, pull, rm, route, doctor) into a single
  summary line, while `/dgx help` stays the progressive-disclosure detail page.
- **Mode**: `newt plan --one-shot --max-leaves 4` on a clean throwaway checkout of
  `main`. **Model**: Qwen3-Coder-Next — the *strongest resident coder* on the dgx node.
- **Grade**: `grade-548.sh` — a behavioral oracle that drives the built `newt` and
  checks the *actual* help output (an orphan/unwired implementation fails it).
- **Real seam**: `fn help_lines()` in `newt-tui/src/lib.rs`.

## Result: not implemented — but it failed *honestly*

```
[Failed] refactor-help-display
✗ verification did NOT pass — work isolated and discarded, NOT landed.
✗ stopped at a failed leaf
remaining (blocked/stalled): add-dgx-summary-docstring, implement-dgx-help-handler, add-test-for-rollup
plan incomplete
grade-run: no crew/* branch (run produced no leaves)
```

No `crew/*` branch, no commits — the repo untouched at base. **Two compounding failures**
(see root cause below): the plan targeted `help_lines` in `newt-cli/src/crew.rs` (where
it does **not** exist), and leaf 1's edit was a lazy placeholder
(`<the full file content remains unchanged>`) that deleted real code and didn't compile.

## The headline: the honesty fix held on a real issue

This is the point of the experiment. The verify gate **caught the bad edit, discarded it
("NOT landed"), and the run reported `plan incomplete` / no crew branch — no false
success.** Contrast the #672 baseline: runs A–E *"completed + consolidated"* while
implementing #548 in 0/N — a **dishonest** green. The trilogy changed the failure mode
from **dishonest** ("✓ complete" over vacuous work) to **honest** ("I tried, it didn't
pass verify, I landed nothing"). **The crew now tells the truth about what it can't do** —
on a real issue, not just a synthetic fixture. That is #677/#675 working.

## Root cause, verified: *newt* mis-grounded the model

The natural reading is "the planner hallucinated the wrong file." It did not. **newt's own
grounding helper fed the planner a false premise**, and the planner faithfully obeyed it.

`fetch_code_grep_hits` (`newt-cli/src/crew.rs:793`) greps the repo for the task's terms
and truncates to the first three hits (`crew.rs:803`, `hits.lines().take(3)`), then the
plan-author prompt says *"implement AT these sites, do not invent file paths."* But
`git grep` is **path-alphabetical**, and for `help_lines`:

```
$ git grep -F help_lines -- '*.rs'
  3 newt-cli/src/crew.rs     ← a doc-comment + 2 test fixtures (DECOYS), sort first
 11 newt-tui/src/lib.rs      ← the real definition (fn help_lines() @ :8273), sorts last
```

`take(3)` keeps the **three `crew.rs` decoys** and **truncates the real definition off the
cliff**. The planner was *told* `help_lines` is in `crew.rs` — so it authored every
subtask against `crew.rs`, where the function does not exist. This is a **deterministic
bug in newt**, reproducible with one `git grep`, not a model capability gap.

The second failure compounded it: asked to edit a file with no `help_lines`, the executor
emitted a lazy `<the full file content remains unchanged>` placeholder — and **the apply
path applied it before the compile error caught it** (`run_crew` partitions edits only on
the fs_write leash, then `workspace.apply()` unconditionally), so a no-op/elision marker
silently overwrites real code and is only caught downstream as a build failure.

## What it localizes

- **Proven robust:** the orchestration fix holds even when the model produces garbage —
  no vacuous green, no faked completion.
- **The remaining gap is two *deterministic* bugs upstream of orchestration**, not "a
  bigger model": (1) the grounding helper truncates the real definition; (2) the apply
  path applies lazy/elision emissions before verifying them.
- **Why T3 passed 3/3 but #548 didn't:** T3 was a single-file fixture with a locked
  `grade_spec` steering each leaf — no cross-crate decoy, no truncated hint. #548 has a
  same-named-function decoy that sorts *before* the real seam, so the `take(3)` bug bites.
- **"Stronger model" has nowhere to go:** #548 already ran on the strongest resident
  coder. A better model fed the same false `crew.rs` hint would likely still go to
  `crew.rs`.

n=1 — but the failure *mode* (honest, not false; a named deterministic bug, not a capability
ceiling) is the robust finding, and it dictates the fix.

## Toward success on this class

From an adversarial design panel (six independent lenses → synthesis). The leverage is
**two small, pure, deterministic fixes** — not a new subsystem, not more horsepower. The
orchestration is already honest; honesty *without* these two fixes just produces a cleaner
failure.

### Build first (each attacks exactly one observed failure)

- **Lever A — fix the grounding helper (small · high impact · attacks mis-ground).**
  In `fetch_code_grep_hits` (`crew.rs:793`), replace `git grep -F <term> | take(3)` with a
  **definition-ranked, untruncated** query — reuse `extract_definitions_rust`
  (`newt-core/src/symbols.rs`) or `git grep -n -e 'fn X' -e 'struct X' -e 'trait X' -e
  'enum X'` — so `fn help_lines` outranks comment/test mentions and the definition is never
  cut off. **Stamp the resolved `<symbol> defined at <path>:<line>` into `Subtask.context`**
  so the executor reads the right file even when no path is named. This is the actual
  root-cause fix; #548 re-grounds to `newt-tui/src/lib.rs` with **no model change**.

- **Lever B — pre-apply lazy-emission gate (small · high impact · attacks placeholder).**
  A pure `lazy_emission_reason(new, prior) -> Option<Reason>` in `newt-core` (sibling to
  `verify_gate.rs`) detecting whole-line elision markers (`remains unchanged`, `<the full`,
  `rest of the file`), drastic shrink-ratio vs the prior file, and no-op bodies. Wire it
  into `run_crew` (`newt-scheduler/src/crew.rs`) **before `workspace.apply()` (~:289)** as a
  second partition: a lazy body is *never applied* — push a deterministic repair string
  ("emit the COMPLETE file verbatim, no elisions") onto `failures` and let the existing
  `max_attempts` loop retry. Add a "no elisions, complete file" line to the `run_crew`
  system prompt (which today never forbids it). Turns silent code-destruction into a precise
  retry.

→ **Then re-run the experiment** (#548, Qwen3-Coder-Next, `--one-shot --max-leaves 4`). One
cheap run tests both root-cause diagnoses at once and is the minimum that could flip #548
from honest-fail to **pass**. It is also a diagnostic fork for the next levers.

### Build next, only if the re-run shows the need

- **Lever C — post-author claim-check backstop (medium · medium · mis-ground).** A pure fn
  beside `plan_sanity` (`crew.rs:340`): for each `(symbol, claimed-path)` a subtask asserts,
  grep the symbol's *definition* and **refute only on positive contradiction** (defined
  elsewhere, not at the claimed path). On refutation: cite the correction, re-author once,
  else honest exit-2. Insurance for "model authors the wrong file *despite* a correct hint";
  most of its value collapses once A stops the helper lying, so don't over-build it into a
  whole module.
- **Lever D — failure-driven re-grounding (medium · medium · both).** On a leaf verify
  `Err`, parse the build error for the unresolved symbol + `file:line`, re-ground
  definition-first (the same ranker as A), re-author that one subtask, retry under a small
  bounded budget. rustc's error is *stronger* evidence than the stale author-time grep. The
  recovery layer; need drops sharply once A+B prevent the bad guess.

### Later, and not a fix for these two failures

- **Lever E — issue→behavioral-spec as `locked_verify` (large · medium).** Synthesize a
  black-box acceptance script (the `grade-548.sh` shape) from the issue and admit it as the
  per-leaf locked gate *only after a base red-check proves it fails-on-base*. Its real,
  distinct value is catching the **unwired-orphan** class (compiles + unit-tests pass but the
  feature isn't hooked up) that the unit-verify misses — so it raises what "done" means. But
  it relocates nothing (doesn't fix mis-ground) and `verify` already catches the placeholder's
  compile error; evaluate it on the orphan class, **not** on #548, which it cannot relocate.

### Demoted / rejected

- **Model escalation + best-of-n sampling** — pure "more horsepower." #548 already ran on
  the strongest resident coder, so escalation has nowhere to climb, and it touches neither
  deterministic root cause. (Its one useful piece — a lazy-edit guard — is Lever B.)
- **"The model ignored a good hint"** framing — empirically false: the hint was *truncated
  wrong*, not present-and-ignored. This matters: it argues for a heavy gate when the
  high-leverage move is fixing the helper that produced the wrong hint.

## Reproduce

```bash
# crew on the real issue
throw=$(mktemp -d); git -C <newt-repo> archive HEAD | tar -x -C "$throw"
( cd "$throw" && git init -q -b main && git add -A && git commit -qm base )
newt plan --goal "<#548 issue text> … implement it" --one-shot --dir "$throw" --max-leaves 4
# behavioral grade
scripts/eval/grade-run.sh "$throw" <base-sha> "$throw/target"   # → grade-548.sh on the built binary
# reproduce the helper bug directly
git grep -F help_lines -- '*.rs' | head -3     # all crew.rs decoys; the newt-tui def is truncated
```

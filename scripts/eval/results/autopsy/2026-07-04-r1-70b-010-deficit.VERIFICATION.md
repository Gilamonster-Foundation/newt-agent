## This is now a pattern, not a one-off

Two independent `/crew-autopsy` runs, on different data, authored by
different agent instances, both hallucinated `behavioral: PASS` for rows
`sweep.tsv` shows as `FAIL` — and this second occurrence affected 4 items at
once, not 1, plus silently dropped a 10th. Root-caused to
`crew-autopsy.workflow.js`'s Inventory phase: when `source` is a bare
comma-separated list of run directories (no `sweep.tsv` present), there is no
ground-truth reference for `behavioral` at all, so the agent guesses from
surface signals (a `.plan.log` ending "✓ plan complete, all N leaves Done"
reflects the crew's own bookkeeping, not the hidden grade's outcome) —
sometimes guessing backwards.

**Filed as newt-agent#918**, with a fix already written and verified
(`node --check` clean): the Inventory phase now accepts an authoritative
`"dir|BEHAVIORAL"` pair format so a caller who already knows each dir's
ground truth (as I did here, from `sweep.tsv`) can pass it through instead of
having it re-derived; the Classify phase gets an explicit "GROUND TRUTH
CHECK" that refuses a `grading-integrity` classification whenever
`item.behavioral` is already FAIL, and requires literal reproduction (not a
diff read) for any claim that a recorded outcome is itself wrong. The
dropped-10th-item gap is filed as a follow-up within the same issue — it
needs a different fix (an explicit in-count-equals-out-count accounting
check).

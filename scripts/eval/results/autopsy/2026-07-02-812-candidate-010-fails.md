## The biggest mover: grading-integrity (6/12)

grading-integrity and worker-ignores-scope tie on raw count, but grading-integrity wins the
comparison on cross-model spread: it shows up in **three of the four models**
(devstral-small-2:24b, qwen3-coder:30b, deepseek-r1:70b) versus worker-ignores-scope's two
(qwen2.5-coder:32b, deepseek-r1:70b). With only one task in this sweep, model spread is the only
axis that distinguishes "this is a property of the harness" from "this is a property of one
model's coding style" — and grading-integrity clears that bar convincingly. In every one of these
six items, the run was logged as behavioral **PASS**, yet re-running the case's own
`tests/grade_spec.rs` against the exact committed HEAD, in an isolated copy of the tree, fails.

## Next lever

**Fix grading-integrity first, before spending another cycle on worker scoping.** The argument:

1. **A broken oracle invalidates every other measurement.** #812's whole premise is that
   leaf-scoping (`worker-ignores-scope`, the mechanism that motivated the fix) improved. But if six
   of twelve items in *this same sweep* were graded PASS on code that the grade spec itself fails
   when re-run, the sweep's PASS/FAIL counts are not trustworthy evidence for *or against* the
   scoping fix. Any n≥5 re-sweep run to validate #812 will inherit the same broken oracle unless
   this is fixed first.
2. **The signal points at a concrete, checkable cause.** The `target-grade-spec-inner` vs.
   `.newt/crew-target` mtime ordering in `tmp.4wLdVhoUpU` is a specific, falsifiable hypothesis
   (stale cached build feeding the inner grader) — cheaper to chase down than re-deriving the
   mechanism from scratch.
3. **worker-ignores-scope still needs attention, but it's the known problem #812 already targets.**
   Three of its six items (`tmp.xD8EEzeBvj`, `tmp.aOk1jan7XV`, `tmp.4nNfHaugIb`, all
   deepseek-r1:70b) share a second symptom — truncated `.plan.log` with no completion — that looks
   like a plan-runner crash/abandonment bug distinct from scope violation per se, and is worth
   splitting into its own mechanism (`plan-run-abandoned`) before the next sweep.
4. **Respect the n lesson already logged for this line of work.** This is n=12 on one case; don't
   generalize the grading-integrity rate itself past this candidate without a wider re-sweep once
   the oracle is fixed.

Concretely: instrument the grading harness to assert `GRADE_SPEC_INNER` compiles against the exact
committed HEAD (fail loudly on any target-dir staleness) before trusting any PASS verdict from

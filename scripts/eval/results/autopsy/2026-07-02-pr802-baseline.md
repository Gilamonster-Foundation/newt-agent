## The biggest mover: worker-ignores-scope (9/17)

worker-ignores-scope wins on both axes that matter: raw count (9 of 17 items, the
single largest bucket) and cross-model spread — it appears in **three of the four
models** (qwen3-coder:30b, qwen2.5-coder:32b, deepseek-r1:70b) and on **both
tasks**. That spread is what rules out "this one model is weak" as the story: the
mechanism is a property of how crew mode hands leaves to workers, not of any
particular model's coding ability. Workers receive a narrowly-scoped leaf
instruction and then do something else entirely — rewrite the whole function on a
"validate-fix" leaf, invent Go files (`main.go`, `summarize.go`,
`path/to/summarize.go`) inside a Rust crate, hand-roll a `Cargo.lock`, or delete
the seed test while "adding a helper".

The cleanest exemplar is the qwen3-coder:30b T2 run (`tmp.kFDGwziEa4`): leaf 1
fixed the bug correctly and the crate was **passing at that commit**; then leaf 2,
whose entire instruction was "Run the specific failing test to verify", rewrote
the function and broke the `0 → "0m 0s"` contract:

> `.plan.log` lines 8-9: "• validate-fix — Run the specific failing test to verify that 90 seconds now produces \"1m 30s\" (after fix-seconds-calculation)"
> `git diff 71d127b f53a3d9 -- src/util.rs` (leaf 2 'validate-fix'):
> ```
> -    format!("{}m {}s", secs / 60, secs % 60)
> +    if minutes > 0 && seconds > 0 {
> +        format!("{}m {}s", minutes, seconds)
> +    } else if minutes > 0 {
> +        format!("{}m", minutes)
> +    } else {
> +        format!("{}s", seconds)
> +    }
> ```

A verify-only leaf converted a PASS into a FAIL. The per-leaf verify gate let it
through because the seed test (90s) still passed; only the hidden spec's edge
cases (`0 → "0m 0s"`, `59 → "0m 59s"`) caught the regression.

## The runner-up: other (8/17)

The "other" bucket is dominated by a distinct, coherent failure that deserves its
own label next round: **plausible-but-nonconforming decomposition**. The worker
does roughly what the leaf asked, in-scope, but the result violates the hidden
spec's structural fences — nested helper functions instead of extracted ones
(all 4 devstral-small-2:24b runs), `pub` helpers where private was required,
`panic!`/`unwrap` bodies the fence whitelist rejects, or a helper named `max`
when the spec demands the exact signature `maximum(nums: &[i32]) -> i32`.
Exemplar (devstral, `tmp.G7guqtaSCn`):

> `git show b670783` (first crew leaf, src/lib.rs):
> ```
>  pub fn summarize(nums: &[i32]) -> String {
> +    fn count_items(nums: &[i32]) -> usize {
> +        nums.len()
> +    }
> ```

The planner's leaf said "Implement it at the definition site of `summarize`" —
the worker read that as *inside* `summarize`. The plan reports `✓ plan complete`
with all leaves `[Done]`, behavior is unchanged, unit tests pass — and the grade
spec fails on "summarize body must not define nested functions". Note that in
these devstral cases the ambiguity originates in the **planner's leaf wording**,
so part of this bucket is upstream of the workers.

Secondary signals worth tracking (not primary mechanisms this round):
`worker-spurious-edits` (hand-rolled `Cargo.lock` in nearly every run, deleted
contract docstrings), `grading-integrity` (plan_rc=124 timeouts on
deepseek-r1:70b where the crew tip graded is a half-finished lineage), and
`fail-stop` residue on plan_rc=1 runs.

## Next lever

**Fix worker leaf-scoping first.** The argument:

1. **It is the modal mechanism (9/17) and it is model-agnostic.** Any fix that
   only tunes one model's prompt leaves two-thirds of the bucket untouched.
   A harness-level constraint — pass the worker an explicit file/function scope
   contract, reject commits that touch files outside the leaf's declared scope,
   and make verify-only leaves genuinely read-only (no write capability at all)
   — attacks all 9 items at once.
2. **The read-only-verify sub-case is nearly free.** Two of the nine (the
   qwen3-coder T2 pair pattern) are PASS-at-leaf-1 states destroyed by later
   leaves that had no business editing. Clamping non-implementation leaves to
   fs_read would have converted at least one FAIL to PASS outright, and it
   composes with the existing OCAP caveat machinery rather than adding prompt
   text.
3. **The "other" bucket needs a taxonomy fix before a code fix.** Its dominant
   sub-pattern (structural nonconformance to hidden fences: nested/`pub`/panicky
   helpers) is partly planner wording ("at the definition site of") and partly
   worker interpretation — split it into `worker-nonconforming-structure` vs
   `planner-ambiguous-leaf` next sweep before spending an engineering cycle on it.
4. **Respect the n lesson from #803.** Per-cell counts here are small; the
   worker-scoping lever should be validated with an n≥5 re-sweep on both tasks
   before claiming lift, exactly as the crew-improvement notes prescribe.

Concretely: implement worker leaf-scoping (scope contract in the leaf handoff +
out-of-scope commit rejection + read-only verify leaves) in newt-agent, then
re-run `scripts/eval/ratchet.sh` at n≥5 against this baseline.

# Hermes-Agent Tools Layer — Survey & Comparison for newt

## 1. How tools are defined and schemed

Every tool file self-registers into a singleton registry at import time (`tools/registry.py:721`, `ToolRegistry.register` at registry.py:356). A `ToolEntry` carries name, toolset, OpenAI-format schema, handler, `check_fn` availability probe, `requires_env`, emoji, per-tool `max_result_size_chars`, and an optional `dynamic_schema_overrides` callable for runtime-config-dependent descriptions (registry.py:78–107). Discovery is AST-based: `discover_builtin_tools` only imports modules containing a *top-level* `registry.register(...)` call (registry.py:43–75). Two notable hardening features:

- **check_fn TTL cache with flake grace** (registry.py:134–197): probes (Docker daemon, playwright) are cached 30s; a failure within 60s of the last success is treated as transient and the last-good True is served — because one flaky `docker version` timeout used to silently strip the whole terminal+file toolset from a subagent mid-session (comment cites issues #21658/#5304).
- **Plugin override governance**: a plugin cannot shadow or deregister a built-in tool without operator opt-in `allow_tool_override`, bound to the module that *defined* the handler so callbacks can't launder overrides (registry.py:307–338, 393–408, 450–500).

## 2. Toolset composition per session

`toolsets.py` defines a shared `_HERMES_CORE_TOOLS` list (toolsets.py:31–82) and composes named toolsets/bundles from it: per-platform bundles (`hermes-cli` at toolsets.py:430, `hermes-discord` at 453), a deliberately constrained webhook set for untrusted third-party content (toolsets.py:86–92), and a `"coding"` **posture** toolset auto-selected when the session starts in a code workspace (toolsets.py:342–367, selected by `agent/coding_context.py`). What a session actually gets is computed in `model_tools.get_tool_definitions` (model_tools.py:279–567): resolve enabled/disabled toolsets → registry `check_fn` filtering → **dynamic schema rebuilds** — the `execute_code` schema is regenerated to list only sandbox tools that actually passed availability (model_tools.py:453–464), Discord schemas are rebuilt from the bot's live intents (466–493), and `browser_navigate`'s description has its "prefer web_search" cross-reference stripped when web tools are absent so the model never hallucinates missing tools (499–513). Then a schema sanitizer normalizes shapes for llama.cpp GBNF (525–535), and finally **Tool Search progressive disclosure**: when MCP+plugin schemas would exceed ~10% of the model's context window, they're replaced by three bridge tools `tool_search`/`tool_describe`/`tool_call` (model_tools.py:537–565; design notes in `tools/tool_search.py:1–27` — core tools never defer, catalog is stateless per assembly). `tool_call` unwraps to the real tool through `handle_function_call` with a defense-in-depth session-scope gate (model_tools.py:1104–1138). The whole result is memoized on (toolsets, registry generation, config-mtime fingerprint) with LRU eviction (model_tools.py:303–353). `toolset_distributions.py` is **not** session machinery — it's probability sampling of toolsets for training-data generation runs (toolset_distributions.py:1–20).

## 3. Output truncation: a three-layer system

Documented explicitly in `tools/tool_result_storage.py:1–23`:

1. **Per-tool caps**, config-tunable via `tool_output:` (`tools/tool_output_limits.py:39–41`): terminal 50K chars, read_file 2000 lines / 2000 chars per line (ported from an opencode PR, header comment).
2. **Per-result persistence** (`maybe_persist_tool_result`, tool_result_storage.py:144–200): a result over the tool's registered threshold (default 100K chars, budget_config.py:17) is written *into the execution environment* via `env.execute()` with stdin piping (explicitly to dodge Linux's 128KB `MAX_ARG_STRLEN`, tool_result_storage.py:100–116) and replaced in-context by a `<persisted-output>` block: 1,500-char newline-aligned preview + file path + "use read_file with offset/limit" (119–141). Retrieval reuses the ordinary `read_file` tool — no dedicated fetch tool. Crucially, `read_file`'s own threshold is **pinned to infinity** to prevent persist→read→persist loops (budget_config.py:10–13).
3. **Per-turn aggregate budget** (`enforce_turn_budget`, tool_result_storage.py:203–254): if all tool results in one assistant turn exceed 200K chars total, the largest non-persisted results are spilled (threshold=0) until under budget. Wired in `agent/tool_executor.py:912/954/1568/1632`.

Compare newt: `spill.rs` triggers at 16K chars with an 800+800 head/tail teaser and redact-on-store, retrieved via a dedicated grep-able `memory_fetch` (`newt-core/src/agentic/spill.rs:1–28`). Newt's thresholds are ~6× tighter (local-model context economy) and its store is in-process, not on-disk-in-env. Hermes's two genuinely different ideas are the **aggregate turn budget** (newt caps per-result only) and the **loop-prevention pin** on the retrieval tool.

## 4. The README "RPC scripts" claim — real, and here's the mechanism

The claim maps to `execute_code` ("Programmatic Tool Calling"), fully wired in `tools/code_execution_tool.py`. The model submits a Python script; the parent generates a `hermes_tools.py` stub module containing typed functions for exactly the intersection of the 7-tool `SANDBOX_ALLOWED_TOOLS` (web_search, web_extract, read_file, write_file, search_files, patch, terminal — lines 62–70) and the session's enabled tools (269–301); spawns a child process; each stub call travels over a Unix domain socket back to the parent (loopback TCP on Windows, lines 1256–1265; file-based request/response polling for docker/ssh/modal/daytona remote backends, 763–911), where it is dispatched through the standard `handle_function_call` (588, 870) — so hooks, middleware, and approval fire per-call. Only the script's stdout returns to the model: "intermediate tool results never enter the context window" (docstring, lines 24–25).

**Safety model**: per-run random RPC token checked with `secrets.compare_digest` (541–546); server-side tool allow-list (552–561); max 50 tool calls (564–571); terminal `background`/`pty` params stripped (484); child env scrubbed by secret-substring blocklist + prefix allowlist (88–207); whole-script approval guard `check_execute_code_guard` runs before spawn, with cron deny mode (approval.py:2696–2756); stdout is ANSI-stripped and secret-redacted (1493–1507); 5-min timeout with psutil process-tree kill (1578–1625). Two modes: `project` (default — session cwd, user's venv python) vs `strict` (isolated tmpdir, 1653–1767).

**What it buys, honestly**: "zero-context-cost" is marketing — it's *one* turn carrying the ~450-word schema plus the script, returning ≤50KB stdout. The real economics: a 10-step pipeline with ~5K-token average results costs 10 inference calls, each re-paying a growing prefix, and leaves ~50K tokens of intermediate results in context; execute_code costs 1 inference call plus only the script-filtered stdout. The schema itself coaches the tradeoff: use it for "3+ tool calls with processing logic between them" or to "filter/reduce large tool outputs before they enter your context"; use normal calls when you "need to see the full result and apply complex reasoning" (1849–1868). The stub bakes in `json_parse`/`shell_quote`/`retry` helpers to preempt common script failures (306–341).

**Stdout capping** is a streaming head+tail drain: 40% head buffer + 60% rolling tail deque, memory-bounded *during* the read, with an omitted-chars notice (1364–1414, 1472–1482) — a stronger shape than post-hoc string capping.

## 5. MCP + delegation

MCP client (`tools/mcp_tool.py`): stdio/HTTP/SSE servers from config; discovered tools register into the same registry under `mcp-<server>` toolsets, refreshed nuke-and-repave on `list_changed` (registry.py:450–464); big MCP surfaces get deferred behind the tool_search bridge. `mcp_serve.py` is the inverse: it exposes Hermes's *messaging conversations* (10 tools) to external MCP clients — not the tool registry (mcp_serve.py:1–28). Delegation (`tools/delegate_tool.py`): children inherit the parent's toolsets minus a hard blocklist — `delegate_task`, `clarify`, `memory`, `send_message`, `execute_code`, `cronjob` (45–54) — depth cap default 1, and subagent threads get an **auto-deny** approval callback by default (74–90). This is essentially newt issue #948 already built, with met-down authority by blocklist rather than by lattice.

## 6. Scale finding

cli.py 743KB, hermes_state.py 275KB, run_agent.py 269KB, ~90 files in `tools/`. The layer works, but the cost shows in cross-module reach-ins (`code_execution_tool._get_or_create_env` imports six private symbols from `terminal_tool`, lines 634–639) and in bug archaeology embedded in comments: #33057/#30882 (approval context lost across threads → sandbox tool calls silently auto-approved dangerous commands), #27303 (env leak), #33924/#57315 (toolset subtraction emptying the tool list).

## Candidate learnings for newt

1. **A script-RPC tool (execute_code analog).** Mechanism: generate a typed stub module for the session's tool subset, spawn a confined child, dispatch each RPC through the normal tool pipeline, return only stdout. Plugs into `newt-core/src/agentic/tools.rs` as one tool; the RPC dispatcher takes the *met-down caveat set* as an explicit value — newt's OCAP lattice is structurally the fix for the ambient-authority bugs hermes had to patch (#33057/#30882). Payoff: collapses grep/read/filter pipelines into one round, directly relieving the 40-round cap and reducing spill/compression load; complementary to crew (crew = inference per role; this = zero-inference plumbing) and to #948 (script = deterministic; subagent = adaptive). Hermes's schema-coached "when to use which" language is worth copying into the LanguagePack-style contract.
2. **Per-turn aggregate output budget.** `enforce_turn_budget` (tool_result_storage.py:203–254): after a tool round, if total results exceed a budget, spill the largest ones even though each is under the 16K per-result cap. Pure function over the round's messages — fits newt's fully-mocked unit tier. Payoff: closes the many-medium-results flood that per-result caps miss.
3. **Retrieval-tool threshold pinning.** `read_file=inf` (budget_config.py:10–13) prevents persist→read→persist loops. Verify newt's `memory_fetch` output is exempt from `tool_offload` re-spilling; if not, this is a live bug class hermes documented.
4. **Streaming head+tail drain for subprocess output** (code_execution_tool.py:1364–1414): rolling-deque tail keeps memory bounded while a runaway process streams gigabytes. If newt's #942/#945 capping buffers the full string first, adopt the streaming shape for exec.
5. **Never advertise the unavailable** (model_tools.py:453–513): dynamic rebuild of schemas so descriptions only mention tools that passed availability. Fits Three Cs — assemble descriptions from data conditioned on the live catalog. Cheap eval-able lever against phantom-reach (#717).
6. **check_fn flake grace** (registry.py:134–197): if newt ever gates tools on MCP-server liveness probes, serve last-good-within-60s instead of stripping tools on one probe timeout.
7. **Threshold-gated deferral for MCP surfaces** (tools/tool_search.py:1–27): newt's #725 deliberately excluded lazy-loading; hermes shows how to add it later without hurting the small case — a no-op below 10%-of-context, core tools never deferred, stateless per-assembly catalog (their cited regression: session-keyed catalogs drift).

## Avoid replicating

1. **Monolithic file scale and private-state reach-ins** (cli.py 743KB; code_execution_tool.py:634–639 importing `_active_environments`/`_env_lock` from another module). Untestable in isolation; violates newt's small-crates + 88% coverage discipline.
2. **Ambient authority via thread-locals/ContextVars.** The `propagate_context_to_thread` wrappers exist because approval context silently vanished across threads, auto-approving dangerous commands (code_execution_tool.py:981–993 comments, delegate_tool.py:60–73). Confused-deputy by construction — authority must be a passed value (caveats), never inherited ambient state.
3. **Secret-substring env scrubbing as a security boundary** (code_execution_tool.py:91–101): a blocklist with a documented false-negative history (CREDS/BEARER/APIKEY added after leaks; "PASS" deliberately skipped for false positives). Use caveat-derived explicit allowlists instead.
4. **Flat string-set toolset algebra.** The bundle/posture subtraction special-casing (model_tools.py:399–424, fixing #33924/#57315 where disabling a bundle emptied the tool list) is what set-difference over names decays into. Newt's lattice meet is the principled version; don't grow a parallel name-set system.
5. **Library code printing to stdout.** model_tools prints ✅/🚫 status; the RPC server must redirect `sys.stdout` to devnull around every dispatch to protect the CLI spinner (code_execution_tool.py:582–592). Newt's separated display layer already avoids this — keep it.
6. **toolset_distributions.py** — probability-sampled toolsets for datagen batches, not agent architecture; irrelevant to newt.

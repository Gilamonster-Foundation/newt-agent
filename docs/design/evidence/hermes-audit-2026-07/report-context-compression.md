# Hermes Context Management & Compression — Verification + Delta vs Prior Study, and newt Comparison

## Scale finding first

Single-file scale has grown since the prior study: `cli.py` 743KB, `gateway/run.py` 995KB (~1MB), `run_agent.py` 269KB, `agent/context_compressor.py` 152KB/3,082 lines (was 1,583 in the prior report — it doubled). The compression subsystem is actively being *extracted* from the monolith: `agent/conversation_compression.py`, `agent/iteration_budget.py`, `agent/bounded_response.py`, `agent/context_breakdown.py` are new modules pulled out of `run_agent.py`. Hermes is mid-refactor toward the small-module shape newt already has.

## trajectory_compressor.py is NOT runtime context management

The 69KB `trajectory_compressor.py` is an **offline training-data post-processor** for SFT datagen: "Post-processes completed agent trajectories to compress them within a target token budget while preserving training signal quality" (trajectory_compressor.py:3-6). It uses a **real HF tokenizer** (`moonshotai/Kimi-K2-Thinking`, :86), targets `target_max_tokens: 15250` with a `summary_target_tokens: 750` Gemini-flash-generated summary via OpenRouter (:100-106), operates on sharegpt `from`/`value` turns, and replaces a middle span with one "human" summary message. Notable mechanism: `_snap_boundary` at both head and tail so the compressed region never orphans a `<tool_call>`/`<tool_response>` pair — "a boundary on a tool turn would leave an orphaned marker and corrupt the training trajectory" (:823-829). It emits per-trajectory + aggregate metrics JSON. The runtime engine remains `agent/context_compressor.py`. The prior study's framing was correct to focus there.

## Prior report verification

Core claims re-verified, line numbers shifted: anti-thrash "last two compressions each saved <10% → stop" now at context_compressor.py:1176-1201; iterative "PREVIOUS SUMMARY / NEW TURNS TO INCORPORATE" prompt at :1842 with `_previous_summary` capture at :1927 and cross-restart rehydration at :2815. Prompt caching (`agent/prompt_caching.py`, 119 lines) still `system_and_3` (4 breakpoints: system + last-3 non-system, prompt_caching.py:86-99) — **new since prior study**: `_can_carry_marker` (:53-75) skips messages whose markers a provider silently ignores (empty assistant tool-call turns, empty tool messages on OpenRouter's envelope layout), so breakpoints aren't wasted; OpenRouter's silent-hang on top-level `role:tool` cache_control is explicitly worked around (:27-32). Stable-prefix discipline extended: `_EPHEMERAL_SCAFFOLDING_FLAGS` (run_agent.py:225-236) marks synthetic empty-response/nudge/verify-on-stop turns as never-persisted because "persisting them poisons the resumed transcript and breaks prompt-prefix cache reuse (#55733)".

## New since the prior study

1. **Compression concurrency lock.** `compress_context` (conversation_compression.py:435) acquires an atomic state.db-backed lock keyed on the *old* session_id with a lease refresher (`_CompressionLockLeaseRefresher`, :75-120), because a parent agent and its background-review fork share a session_id and could both compress overlapping snapshots, double-rotating the session and orphaning a child ("Damien's repro shape", :506-520). Loser aborts cleanly; caller detects no-op via `len(returned) == len(input)`.
2. **In-place compaction rollout.** `compression.in_place` (#38763, :485-494, default False) rewrites messages + system prompt but keeps the same session_id — eliminating "the session-rotation bug cluster." Hermes is admitting session rotation on compaction was a mistake.
3. **Temporal anchoring.** The summarizer prompt injects the current date and demands completed actions be rewritten "as a completed, dated, past-tense fact rather than an open instruction… Never leave a finished action worded as if it still needs doing" (context_compressor.py:1742-1758, regression-tested in test_context_compressor_temporal_anchoring.py). Directly attacks re-execution of completed side-effecting actions after resume.
4. **Reasoning-content replay matrix.** `copy_reasoning_content_for_api` + `reapply_reasoning_echo_for_provider` (agent_runtime_helpers.py:2714-2846): DeepSeek/Kimi/MiMo thinking modes **require** `reasoning_content` echoed on every replayed assistant tool-call turn (400 without it, #15250/#17400), while strict providers (Mistral/Cerebras/Groq) **422 on the field's presence** (#45655). Hermes reconciles idempotently before *every* request (fallback can switch providers mid-conversation), pads with `" "` (not `""` — DeepSeek V4 Pro rejects empty string, #17341), never leaks one provider's CoT to another (:2749-2768), detects require-side providers by **host, not model name** (run_agent.py:5462-5470 — OpenRouter re-exports reject echoes), and model-gates Gemini `thought_signature`/`extra_content` stripping (run_agent.py:5548-5560). Plus `_is_thinking_only_assistant` drop/merge for Anthropic's "final assistant content cannot be thinking" rule (run_agent.py:3675-3750). This whole layer is *N-provider quirk absorption*.
5. **Tool-output bounding, centralized + spill.** `tools/tool_output_limits.py` centralizes previously-hardcoded caps behind `tool_output:` config (defaults: 50,000 chars terminal, 2,000 lines / 2,000 chars-per-line read_file). Terminal truncation is 40% head / 60% tail with an omitted-count notice (terminal_tool.py:2708-2717). `web_extract` head+tail truncates at 15,000 chars, **spills full text to disk (capped 2MB)** and — the nice touch — the footer computes `middle_start_line = head.count("\n") + 2` and emits a concrete `read_file path=… offset=N limit=200` command so the model's first paging read lands in the omitted gap (web_tools.py:536-549). Hook output spills over 10,000 chars similarly (hook_output_spill.py:24-26).
6. **`context_breakdown.py`** — live per-category token breakdown (system/tools/rules/skills/mcp/subagents/memory/conversation) using the same chars/4 heuristic as the compression threshold "so numbers align" (:1-7). A `/context`-style observability surface.
7. **File-read dedup interacts with compaction:** `reset_file_dedup(task_id)` on every compression because "if the model re-reads the same file it needs the full content, not a 'file unchanged' stub" (conversation_compression.py:950-957) — a cache-invalidation coupling newt should note if it ever adds read-dedup.
8. **Lazy feasibility probe** — aux-model + context-length check deferred to first compression attempt, saving ~400ms per short session (conversation_compression.py:469-483).

## Hermes vs newt — coverage differences

Hermes handles that newt doesn't: cross-provider reasoning-echo reconciliation (newt is more provider-stable, but any DeepSeek/Kimi support will hit this wall); iterative summary-of-summary with cross-restart rehydration; temporal anchoring; compaction concurrency locking; last-user-message structural anchor + verbatim Active Task field; probe-tier context discovery with provenance-gated caching; image token flat-costing; live context breakdown UI. Newt handles what hermes doesn't: **grep-able spill retrieval** (hermes spills web/hook output to disk but tool_offload's `memory_fetch` over a spill store is more general — hermes's per-tool one-liner replacement in pruning is *lossy with no retrieval path*); **per-model context_tokens budgets as data** (hermes's window resolution is a 10-step imperative waterfall vs newt's model cards); redaction as a policy stage (hermes redacts summarizer input/output but tool outputs flow unredacted); harness-run verification; hidden-grader eval gates on compression levers (hermes ships levers on issue-count evidence, not A/B).

## Candidate learnings for newt

1. **Temporal anchoring in the summary prompt.** Mechanism: inject today's date; require completed actions be rewritten as dated past-tense facts (context_compressor.py:1742-1758). Plugs into newt's redacted-LLM-summary stage prompt. Payoff: prevents re-execution of side-effecting actions (emails, pushes, PR creation) after compaction/resume — cheap, testable with a fixture transcript, gate-able with the existing sweep harness.
2. **Iterative summary-of-summary + rehydration.** Mechanism: retain previous summary, feed as "PREVIOUS SUMMARY / NEW TURNS TO INCORPORATE, continue numbering" (:1842); on resume, scan transcript for the summary-prefix marker and reclaim it as `_previous_summary` instead of re-summarizing it (:2815). Plugs into newt's marker-assembly stage — newt already emits markers; teach the summarizer to recognize its own prior marker. Payoff: kills the lossy-telescope decay across multiple compressions on long crew flights.
3. **Last-user-message tail anchor + verbatim Active Task + end-of-summary marker.** Mechanism: structural guarantee the newest user message is never summarized (`_ensure_last_user_message_in_tail`), template's first field copies the request verbatim, explicit "END OF CONTEXT SUMMARY — respond to the message below" marker for weak models (hermes bugs #10896/#11475/#14521). Plugs into newt's boundary stage. Payoff: matters most for newt's small local models, exactly the population hermes observed misreading summaries as fresh input.
4. **Paging hint on spilled/truncated output.** Mechanism: compute the omitted-middle's start line and emit a ready-to-run fetch command in the truncation footer (web_tools.py:536-549). Plugs into tool_offload's head+tail marker — newt already has `memory_fetch`; add the concrete invocation with offset. Payoff: fewer wasted rounds re-fetching the head the model already saw; trivially A/B-able on read-heavy evals.
5. **Effectiveness-gated anti-thrash telemetry (extend CompressState).** Mechanism: measure savings% per compaction, two consecutive <10% passes disable auto-compress and tell the user (:1176-1201), cooldown timers on summarizer failures, loud-but-recovered warnings on broken aux-model config. newt's CompressState is anti-thrash by design; the delta worth taking is the *savings-percentage measurement + user-facing "consider starting fresh" escalation*.
6. **Context breakdown as an observability command** (context_breakdown.py): per-category token attribution aligned to the same estimator the compressor thresholds use. Plugs in as a newt CLI/TUI command over existing budget accounting; payoff is operator trust and tuning data for per-model `context_tokens`.

## Avoid replicating

1. **The provider-quirk reasoning-echo matrix as inline conditionals.** ~200 lines of host-sniffing (`base_url_host_matches("api.kimi.com")`…), space-pad magic, and per-provider strip/inject rules hardcoded in helpers (agent_runtime_helpers.py:2714-2846, run_agent.py:5456-5505) — with a hand-rolled memo cache justified by "~16 invocations per turn." This is exactly what newt's three Cs forbid: if newt ever needs reasoning replay, it belongs in model cards / family defaults (`reasoning_echo: require|forbid|ignore`), not code.
2. **Session rotation on compaction.** Hermes rotated session_ids per compaction, spawned the "orphaned child session" bug cluster, then needed a state.db lock + lease refresher (conversation_compression.py:75-120, 500-530) and is now rolling out `in_place` compaction to undo the design (#38763). newt should keep one durable session identity across compressions — adopt the *lesson*, skip the lock machinery the mistake necessitated.
3. **10-step imperative context-length waterfall with runtime probe tiers as the primary mechanism** (model_metadata.py:1428-1714). Provenance-gated caching is clever, but it exists because hermes supports dozens of providers with unknown windows. newt's model cards already make the window declared data; adding live `/models` probes and error-text regex parsing would trade determinism for coverage newt doesn't need. (If a card is missing, fail loud, don't probe-guess.)
4. **Estimator-only token accounting (chars/4 everywhere, no tokenizer)** compensated by three separate estimators and flat image constants. Workable, but hermes's own datagen tool reaches for a real tokenizer the moment accuracy matters (trajectory_compressor.py:86,357). newt's per-model budgets should keep provider-reported usage as ground truth and treat estimates as pre-flight only — hermes's `prompt_tokens`-only rule (completion/reasoning tokens don't occupy the window; thinking models inflate them, run_agent.py:15316-15323) is the one accounting detail worth keeping.
5. **Monolith-first, extract-later module strategy.** `gateway/run.py` at ~1MB and `cli.py` at 743KB mean the manual `/compress` path, threshold wiring, and engine config live thousands of lines apart from the compressor; hermes needed forwarder shims (`run_agent` re-exports for tests) to extract anything. Findings ported from other agents (openclaw, opencode) arrive as vendored modules with issue-number archaeology instead of specs — evidence of debugging-driven accretion. newt's small-crate + eval-gated-lever discipline is the correct inverse; nothing about hermes's velocity justifies relaxing it.

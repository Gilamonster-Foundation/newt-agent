# Hermes-Agent Engineering Shape Survey

All paths relative to `hermes-agent@830165473`.

## Repo layout and single-file scale

Non-test Python is ~635K LOC. The core is deliberately concentrated in god-files: `cli.py` = **16,184 LOC** (744KB), `gateway/run.py` = **20,526 LOC**, `hermes_state.py` = 6,322 LOC, `run_agent.py` = 6,013 LOC (the ~240KB figure). This is acknowledged, not accidental: AGENTS.md's rubric lists "Refactor god-files into clean modules... is wanted work, even when the diff is huge and mechanical" (AGENTS.md:66-71) — they are paying a continuous extraction tax on a monolith that keeps regrowing. The stated design stance is "expansive at the edges and conservative at the waist" (AGENTS.md:49-51): platforms/providers/models grow freely, but new *core model tools* are the guarded resource because "every tool ships on every API call" (AGENTS.md:72-77).

## Tests — real numbers

- **1,925 test files, ~36,900 test functions, 711K LOC of tests** — the test corpus is *larger than the source*. This answers "can you even test a 630KB cli.py?": yes, but only via heavy machinery.
- **Isolation machinery is the tell.** `tests/conftest.py:36-50` documents that every test *file* runs in a freshly-spawned `python -m pytest <file>` subprocess (via `scripts/run_tests_parallel.py`) because "cross-file state leakage (module-level dicts, ContextVars, caches)" was otherwise unmanageable; a subprocess-per-*test* experiment was "too slow at ~17k tests". Per-file interpreter spawning is the direct cost of module-level state in giant files.
- **Hermetic invariants are enforced, not aspirational**: conftest strips every `*_API_KEY/_TOKEN/_SECRET...`-shaped env var plus an explicit blocklist (tests/conftest.py:55-100), redirects `HERMES_HOME` to a tempdir, pins TZ/LANG/PYTHONHASHSEED (tests/conftest.py:1-20).
- **Live-system guard with a canary self-test**: after tests SIGTERMed the developer's real gateway "5+ live gateway kills in 3 days," a guard blocks `os.kill`/`killpg`/etc. against foreign PIDs, and `tests/test_live_system_guard_self_test.py:1-17` exists purely to fail if anyone weakens the guard or adds a new kill primitive without covering it.
- **Tiers**: default unit tier (hermetic, CI-gating); `integration` marker excluded by default via `addopts = "-m 'not integration'"` (pyproject.toml:359-366) — these need live API keys and are partly print-based scaffolding with a hand-rolled `log_result` harness (tests/integration/test_web_tools.py:14-125); `tests/stress/` (real subprocesses, race/fuzz invariants, explicitly not run by the canonical runner — tests/stress/README.md:1-15); `tests/manual/`. So the ~37K gating tests are the hermetic tier only.

## CI — what actually gates a PR

`ci.yml` is an orchestrator: a `detect-changes` classifier runs once and lane-gates sub-workflows (Python touched → tests+lint; frontend → typecheck; etc.), failing open on push to main (ci.yml:29-49). A single **`all-checks-pass`** aggregate job is the only branch-protection requirement (ci.yml:137-151). Required: tests, lint, typecheck, docs-site, history-check, contributor-check, uv-lockfile, docker-lint, supply-chain, osv-scanner. Notably: `# we don't require docker to pass rn because it's so slow lol` (ci.yml:150).

- **Tests in CI**: 8 duration-balanced slices (LPT from a cached `test_durations.json`, tests.yml:19-38), per-file subprocess isolation, `uv sync --locked`, API keys explicitly blanked (tests.yml:110-115). 30-min timeout per slice.
- **Lint is nearly all advisory.** Only ONE ruff rule blocks merge — PLW1514 (unspecified-encoding), kept because of three Windows cp1252 corruption regressions; "All other lints are intentionally disabled... while we wrangle typechecks" (pyproject.toml:376-388). The rest is a ruff+ty *diff comment* that always exits zero (lint.yml:1-9).
- **No coverage gate anywhere.** No mypy gate (ty is advisory).
- **Governance checks born from incidents**: `history-check.yml:1-14` rejects PRs with no merge-base with main (a May 2026 orphan-history merge collapsed ~1,500 files of blame onto one commit); `contributor-check.yml` blocks merges whose author emails aren't in an `AUTHOR_MAP` — attribution is CI-enforced.

## Velocity and who spends it

**3,886 commits since 2026-06-06 across 566 distinct authors.** Maintainer core: Teknium ~1,124 (two identities), Brooklyn Nicholson ~585, kshitij ~460. Commit-type breakdown: **2,092 fix (54%)**, 454 feat, 270 test, 243 chore, 150 refactor, 141 docs. Sampled subjects show what the fix-mass is: chains of follow-up fixes to the same feature (e.g., four consecutive commits tuning Codex gpt-5.4/5.5 compression "autoraise" thresholds and deduping its notice), platform/TUI/gateway/cron edge cases with 5-digit issue numbers (#59805), and recurring `chore: add X to AUTHOR_MAP for #NNNNN salvage` — a real "salvage external work by cherry-picking so authorship survives" culture (AGENTS.md:92-95). The velocity is majority *defect servicing of an aggressively expanding surface*, coordinated across hundreds of drive-by contributors.

## Docs, plugins, config

- **AGENTS.md (1,356 lines) is an intent layer, explicitly dual-audience**: "For humans and for your own work" AND "For automated review (the triage sweeper)" with three machine-actionable close reasons (`implemented_on_main`, `cannot_reproduce`, `incoherent`) and explicit *when-NOT-to-close* rules — taste-based rejections stay human (AGENTS.md:29-42). It includes the **Footprint Ladder** (extend existing → CLI+skill → service-gated tool → plugin → MCP catalog → new core tool last resort, AGENTS.md:182+), anti-patterns ("change-detector tests", "lazy-reading escape hatches on instructional tools", "speculative infrastructure", AGENTS.md:96-120), and full architecture maps of the god-files. CONTRIBUTING.md is 1,008 lines with a Spanish translation.
- **Plugins**: `plugin.yaml` manifests scanned from `plugins/<name>/` (flat or category layout) plus pip entry-point plugins (`hermes_cli/plugins.py:1490-1540, 1660-1873`; the loader itself is 2,333 LOC). A wheel-packaging incident (manifests not shipped → zero plugins found) is documented inline at pyproject.toml:345-354. Policy: third-party-product plugins are rejected from the tree and must ship as standalone repos (AGENTS.md:128-138).
- **Config surface**: `cli-config.yaml.example` = 1,429 lines; `.env.example` = 476 lines. Hard rule: `.env` is secrets-only; all behavior lives in config.yaml — PRs telling users to set behavioral env vars are rejected (AGENTS.md:100-106).

## What the shape buys vs. costs

It buys **massive parallel contributor throughput**: 566 authors/month can land work because (a) the intent layer makes accept/reject criteria explicit and partially automatable, (b) hermetic per-file test isolation means any drive-by PR can run 37K tests without environmental flakiness, (c) lane-gated CI keeps PR latency tolerable, (d) attribution/salvage culture keeps contributors returning. It costs: god-files that force subprocess-per-file testing and made lint/typecheck gates politically impossible (one blocking rule!), no coverage ratchet, a 54%-fix commit stream servicing regressions on the expanding edge, and test LOC exceeding source LOC.

## Candidate learnings for newt

1. **Guard canary self-tests** (tests/test_live_system_guard_self_test.py). Mechanism: any safety invariant in the test harness gets a dedicated test file that *attacks the guard* (signal PID 1, `kill -1`) and asserts refusal, so weakening the guard is itself a red test. Plug-in point: newt's fully-mocked unit tier and the OCAP caveat lattice — write canary tests that attempt real fs/exec/net escapes through the mock layer and through a floor-level caveat set, asserting denial. Payoff: newt's "no real fs/network" bar and the Lean-specced enforcement floor become regression-protected properties, not conventions.
2. **The Footprint Ladder as a written decision procedure** (AGENTS.md:182). Mechanism: an ordered, documented ladder for "where does a new capability live," justified by per-API-call cost of tool schema. Plug-in: a `docs/decisions/` entry for newt ordering: LanguagePack/model-card data file → workflow-steer TOML → crew role → MCP → new core tool last. Payoff: guards newt's context economy (tool_offload/prune exist precisely because schema+output volume is the scarce resource) with a triage rule instead of case-by-case debate; matches the Three Cs.
3. **Dual-audience contribution rubric with explicit when-NOT-to-close rules** (AGENTS.md:29-42, 96-138). Mechanism: intent doc written to be executed by an automated triage sweeper, with a closed enum of machine-safe close reasons and taste calls reserved for humans. Plug-in: newt's `github_pr` / `tdd_peer_review` workflow-steer TOMLs — encode accept/reject/escalate criteria as data the navigator role judges against. Payoff: crew PR review gets consistent, auditable judgments; directly reusable if newt-agent takes outside contributors.
4. **Single aggregate required check + change-lane gating** (ci.yml:29-49, 137-151). Mechanism: one `detect-changes` classifier, lane-conditional sub-workflows, one `all-checks-pass` job for branch protection, failing open on push. Plug-in: newt's workspace CI — gate clippy/test/Lean-check lanes by touched paths, keep one required check. Payoff: PR latency stays flat as the workspace grows; branch protection config never drifts.
5. **Merge-base history check** (history-check.yml:1-14). Mechanism: trivially cheap `git merge-base` guard against orphan-history PRs, written after a real blame-destroying incident. Plug-in: copy nearly verbatim into newt CI. Payoff: eliminates an unrecoverable failure class for ~10 lines of YAML — especially relevant given newt's worktree-heavy crew landing flow (memory already records `git checkout -B` worktree-guard bypasses).
6. **Anti-pattern glossary in test guidance**: "behavior contracts over snapshots / don't write change-detector tests" and "no lazy-reading escape hatches on instructional tools" (AGENTS.md:87-91, 107-110). Plug-in: newt's contributor docs and the inertness-oracle review checklist. Payoff: names failure modes newt's eval discipline already fights, cheaply transferring the operator's taste to crew agents.
7. **Belt-and-suspenders credential stripping in the canonical runner** (tests/conftest.py:55-100, scripts/run_tests.sh header). Plug-in: newt's test-support crate clears `*_API_KEY`-shaped env at harness init even though the unit tier is mocked. Payoff: cheap defense against a future test accidentally reaching a real provider.

## Avoid replicating

1. **God-file architecture** (cli.py 16,184 / gateway/run.py 20,526 LOC). It *forces* subprocess-per-file test isolation (tests/conftest.py:36-50 — module-state leakage was otherwise unmanageable), makes lint gates unratchetable, and generates the perpetual "extract mixins" refactor tax AGENTS.md:66-71 institutionalizes. Hermes tolerates it because 566 contributors can grep one file; newt is one operator with small crates, cheap incremental compiles, and in-process test isolation for free. Nothing here transfers.
2. **Advisory-only lint/typecheck with a single blocking rule** (pyproject.toml:376-388, lint.yml:1-9). "Intentionally disabled while we wrangle typechecks" is the accumulation failure newt's `clippy -D warnings` zero-warnings policy exists to prevent. Once gates open they don't re-close at 635K LOC.
3. **No coverage gate.** Hermes compensates with sheer test volume (37K tests) but nothing structurally prevents untested paths; newt's 88%/80% floor is a ratchet worth keeping precisely because it's enforceable at newt's crate sizes.
4. **Live-key, self-harnessed integration "tests"** (tests/integration/test_web_tools.py:14-125 — requires real API keys, prints pass/fail via its own `log_result`, excluded from CI by pyproject.toml:366). newt's model is strictly stronger: harness-run verification, hidden `grade_spec.rs` graders, Fisher-exact gates. Don't import "manual live scripts filed under tests/".
5. **Waiving slow checks from the gate** ("we don't require docker to pass rn because it's so slow lol", ci.yml:150). The honest comment doesn't make the hole smaller. Fix the check's speed or keep it required; a documented-but-unenforced gate decays into a permanently green-optional lane.
6. **A 1,429-line monolithic config example** (cli-config.yaml.example). It's the downstream symptom of "expansive at the edges" — every feature grows the single example file. newt's Three-Cs approach (model cards, family defaults, droppable TOMLs) keeps config surface federated and per-domain; keep it that way rather than accreting one canonical mega-example.
7. **Fix-dominated velocity as a steady state** (2,092 of 3,886 commits are `fix`, with visible multi-commit fix chains per feature, e.g., the gpt-5.4/5.5 compression-autoraise sequence). That ratio is the recurring interest payment on aggressive surface expansion with advisory gates. newt's smaller, eval-gated lever adoption (n≥5 sweeps, inertness oracle) is the deliberate opposite; adopting hermes-style edge expansion would import the fix-treadmill with it.

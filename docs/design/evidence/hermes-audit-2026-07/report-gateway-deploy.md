# Hermes-Agent Survey: Gateway, Platforms & Deployment (vs newt-agent)

## Scale, first

Hermes is ~1.35M lines of Python (incl. tests) in one repo. The load-bearing files are monoliths: `gateway/run.py` = 20,526 lines (995KB), `cli.py` = 16,184 lines (743KB), `hermes_cli/main.py` = 14,177, `tui_gateway/server.py` = 13,898, `gateway/platforms/base.py` = 5,623, `cron/scheduler.py` = 3,637. This is not incidental — the comment archaeology inside these files (issue numbers #8340, #38249, #58818 inline in `tools/environments/base.py:571`, `base.py:385`, `gateway/run.py:19840`) shows a codebase that grows by accreting fixes into hot files rather than decomposing. The single-file scale is itself the strongest "do not replicate" finding.

## Terminal backend abstraction (the best seam in the repo)

Six backends live in `tools/environments/`: `local.py` (1,207 LOC), `docker.py` (1,460), `ssh.py` (375), `singularity.py` (265), `modal.py` (478, plus `managed_modal.py` 282), `daytona.py` (270), all subclassing `BaseEnvironment` in `tools/environments/base.py` (955 LOC). The design is genuinely clean:

- **Spawn-per-call + session snapshot.** Every command is a fresh `bash -c`; statefulness is simulated by capturing `export -p` + `declare -f` + `alias -p` into a snapshot file at init (`base.py:353-446`) and re-sourcing it before each command (`base.py:491-494`), re-dumping env after (`base.py:510-514`, atomic `mv` with `$BASHPID` temp names to close a torn-write race, `base.py:396`). CWD persists via an in-band stdout marker `__HERMES_CWD_{session}__` parsed and stripped from output (`base.py:281`, `base.py:837-869`) or a temp file for local. This is why Modal and local shell are interchangeable: the contract is just "run this bash string, give me output + exit code."
- **ProcessHandle protocol** (`base.py:189-204`): `poll()/kill()/wait()/stdout/returncode` — `subprocess.Popen` satisfies it natively; SDK backends (Modal, Daytona) wrap their blocking exec in `_ThreadedProcessHandle` (`base.py:207-273`), which fakes a stdout pipe via `os.pipe()` and wires `kill()` to `sandbox.terminate`. Stdin differences are handled by a single class flag `_stdin_mode = "pipe" | "heredoc"` (`base.py:299`; Modal sets `"heredoc"` at `modal.py:171`, embedding stdin as a shell heredoc, `base.py:534-537`).
- **One shared wait loop** (`base.py:543-820`): select()-based non-blocking drain (fixes the backgrounded-grandchild-holds-the-pipe hang, #8340 at `base.py:570`), adaptive 5ms→200ms poll (`base.py:770-778`), interrupt→returncode 130, timeout→124, KeyboardInterrupt→process-group kill so orphans don't survive agent death (`base.py:779-799`; local uses `start_new_session` + `os.killpg`, `local.py:1044-1124`).
- **Selection is a config string** dispatched in `_create_environment` (`tools/terminal_tool.py:1390-1520`), keyed by `task_id` for environment reuse and snapshot naming. Remote backends get file sync via a `_before_execute()` hook (`base.py:875-883`) driving a `FileSyncManager` (`environments/file_sync.py`) that pushes credentials/skills into the sandbox.
- **Serverless hibernate/wake** is Modal filesystem snapshots: on `cleanup()`, `sandbox.snapshot_filesystem` persists an image id into `~/.hermes/modal_snapshots.json` keyed by task (`modal.py:442-469`, store at `modal.py:34`); next environment creation for that task restores from the snapshot as the base image, falling back to the plain image on failure (`modal.py:196-280`). Separately, the *gateway itself* can scale to zero on Fly: `gateway/scale_to_zero.py:1-28` is a decision layer that drives the relay transport's `go_dormant()` while Fly's `autostop:"suspend"` + wakeUrl autostart freeze/resume the process — explicitly hosted-infra machinery.

## Gateway, platforms, delivery

One asyncio process (`start_gateway`, `gateway/run.py:19855`; `main()` at 20411). Platform adapters subclass `BasePlatformAdapter` (`gateway/platforms/base.py:2253`) with abstract `connect/disconnect/send` (`base.py:2863-2888`) plus **capability flags instead of per-platform branching**: `supports_code_blocks` (2272), `supports_async_delivery` — stateless adapters set False and tools refuse to promise post-turn delivery (2274-2288), `splits_long_messages` (2290-2297), `typed_command_prefix` (2299-2310), `supports_inchannel_continuable` (2312-2324). Telegram/Discord/Slack/Matrix/etc. are *plugins* under `plugins/platforms/` self-registered through `gateway/platform_registry.py:1-80` (factory + check_fn + validate_config + required_env + install_hint); only WhatsApp-Cloud/Signal/Weixin/BlueBubbles remain built-in in the `_create_adapter` if/elif (`gateway/run.py:8460-8530`). Voice: adapters download media; the gateway auto-transcribes inbound voice before the agent sees it (`gateway/run.py:14716-14790` → `tools/transcription_tools.transcribe_audio`, default backend local faster-whisper, no API key; groq/openai optional, `transcription_tools.py:7-10`).

**Cross-platform continuity is weaker than marketed.** Sessions are keyed per `(namespace, platform, chat_type, chat_id, thread_id[, user])` (`build_session_key`, `gateway/session.py:856-916`) — there is no unified cross-platform conversation. Continuity is stitched from three mechanisms: (1) delivery-mirroring, which appends sent messages into the *target* chat's transcript so the receiving-side agent has context (`gateway/mirror.py:1-55`, with a role="user" subtlety to avoid assistant→assistant alternation breakage, issue #2221); (2) FTS5/SQLite session search with anchored scroll windows and zero LLM cost (`tools/session_search_tool.py:1-30`) — notably the same bm25-not-embeddings choice newt already settled on; (3) a channel directory mapping friendly names → chat ids, rebuilt every 5 min with a user-editable alias overlay (`gateway/channel_directory.py:1-27`).

## Cron

The scheduler is in-process: a daemon thread ticks every 60s (`gateway/run.py:20308-20318` via `cron/scheduler_provider.py`; file lock `~/.hermes/cron/.tick.lock` guards multi-process overlap, `cron/scheduler.py:7-9`). Jobs run a full agent turn in thread pools, then `_deliver_result` (`cron/scheduler.py:1308-1420`) resolves targets (`origin` chat captured at creation, explicit `platform:chat_id`, or per-platform "home channel" env vars, `scheduler.py:958-1163`), prefers the **live adapter** on the gateway loop (required for E2EE, e.g. Matrix) and falls back to a standalone HTTP send (`scheduler.py:1341`, `1806`). Two mechanisms stand out: the **wake gate** — a job's pre-run script's last stdout line `{"wakeAgent": false}` skips the LLM run entirely, and an empty-output data script also skips (`scheduler.py:2041-2065`, `2096-2107`); and **continuable cron threads** — the delivery seeds a session in the target thread so a user reply continues the job in context (`scheduler.py:622-736`). Failure delivery is deliberately summarized to one line, details staying on disk (`scheduler.py:50-100`).

## Operational story

One process, supervised externally: `hermes_cli/gateway.py` installs/manages systemd user/system units or launchd (`gateway.py:94-152`), restart is requested by exiting 75 (EX_TEMPFAIL) and letting the supervisor relaunch (`gateway/restart.py:5-13`); exit 78 marks fatal config so s6 stops restarting (Docker path). Graceful shutdown drains cron/housekeeping threads without blocking the event loop (deadlock #58818 documented at `run.py:19834-19845`). There's a restart-loop guard, shutdown forensics, memory monitor, and cgroup cleanup as separate gateway modules — evidence that 24/7 single-process operation needed a lot of scar tissue.

## Candidate learnings for newt

1. **The `BaseEnvironment` seam: bash-string + snapshot-sourcing + CWD marker.** Mechanism: abstract execution to "spawn `bash -c <wrapped script>`, return output+exit," with statefulness reconstructed from an env snapshot file and an in-band CWD marker (`tools/environments/base.py:353-527`). Plug-in point: newt's captured-shell / exec tool (`docs/design/captured-shell-cross-platform.md` territory) and wyvern-agent's headless tier — a Rust `trait ExecBackend { fn run_bash(&self, script) -> Handle }` would let local, SSH-to-DGX, and a container backend share one wait/interrupt/timeout loop, exactly serving the operator's DGX + homelab workflow. Payoff: remote execution without a second agent deployment; the OCAP exec caveats attenuate the *script*, orthogonal to *where* it runs. The ~950 lines of base.py encode a decade of edge cases (grandchild pipe hang, torn snapshot writes, orphan process groups) worth porting as tests.

2. **Task-keyed filesystem snapshot for hibernate/resume.** Mechanism: on backend cleanup, snapshot the sandbox filesystem and persist `{task_id: snapshot_id}`; on next creation, restore-or-fallback (`modal.py:442-469`, `196-280`). Plug-in: newt crew worktrees / long-lived remote sessions on the DGX — a cheap analog is `zfs`/overlayfs snapshots or even tar of the worktree keyed by task. Payoff: resumable remote work across machine sleep without keeping anything running.

3. **Cron wake gate.** Mechanism: a $0 pre-run script whose last stdout line `{"wakeAgent": false}` (or empty data output) skips the LLM turn entirely (`cron/scheduler.py:2041-2065`, `2096-2107`). Plug-in: newt's mesh/mobile-nudge design and any scheduled headless run (wyvern) — the harness runs the check, the model only wakes on signal. Payoff: scheduled monitoring (CI red? disk full? PR stale?) at script cost, LLM cost only on events. This composes perfectly with newt's "harness runs verification" law.

4. **Capability flags on the delivery surface, not per-platform branching.** Mechanism: `supports_async_delivery` etc. read via `getattr(adapter, flag, default)` with fail-safe defaults (`gateway/platforms/base.py:2274-2324`); crucially, tools consult the flag *before promising* background delivery. Plug-in: newt's mesh `NewtSessionService` and any future notification sink (ntfy/Telegram single-channel) — declare capabilities in the descriptor (newt's mesh doc already has `CapabilityDescriptor`-shaped handshake ideas; hermes's relay contract at `gateway/relay/transport.py:1-60` is the same shape). Payoff: adding a sink never touches core loop code — this *is* newt's Three Cs applied to delivery.

5. **Delivery-mirror + one-line failure summaries.** Mechanism: out-of-band sends are appended to the receiving conversation's transcript with role="user" to avoid alternation breakage (`gateway/mirror.py:26-55`); cron failures deliver one line, details stay on disk (`scheduler.py:50-100`). Plug-in: newt nudge/notification path — when a scheduled or crew result is pushed to the operator's phone, mirror it into the conversation-recall store (SQLite FTS5) so the next interactive session can "see" what was sent. Payoff: continuity without a unified session model — hermes proves you don't need one.

6. **Wake-gate-adjacent validation of a settled newt decision:** hermes's own long-term recall is FTS5 + anchored windows + bookends with "No LLM calls anywhere" (`tools/session_search_tool.py:1-30`) — independent convergence with newt's embeddings-rejected recall decision.

## Avoid replicating

1. **The single gateway mega-process and its file monoliths.** `gateway/run.py` at 20.5k lines, `cli.py` 16k, 1.35M lines total. The inline issue archaeology (#8340, #38249, #58818, #51228) shows every 24/7-messaging edge case becomes another paragraph in a hot file. newt's small-crates + clippy -D warnings + 88% coverage bar is incompatible with this growth mode; adopting a resident multi-platform gateway would import the maintenance profile with it.

2. **Six-platform (really ~25 with plugins) chat breadth.** `plugins/platforms/` has 20 adapters plus built-ins; each drags per-platform quirks into core semantics (Telegram DM-topic reply anchors leak into shared helpers at `platforms/base.py:56-105`; audio-format routing per platform at `base.py:30-35`, 113+). The operator needs *one* reliable nudge channel (mesh app or a single messenger), not a matrix. Product breadth here is hermes's telescope, not newt's.

3. **Managed/hosted execution tiers (managed Modal via "Nous Tool Gateway", Daytona, Fly scale-to-zero).** `managed_modal.py:36+` routes exec through a vendor gateway; `scale_to_zero.py:11-13` is gated by a NAS "Labs" toggle env stamp on hosted infra. This is SaaS plumbing with vendor lock-in — directly against newt's local-first, replaceable-tools doctrine. If newt wants remote exec, the SSH backend pattern (375 LOC, `environments/ssh.py`) over the operator's WireGuard is the right-sized slice.

4. **Bash-snapshot state simulation as a *security* boundary.** Hermes's env snapshot re-sources arbitrary captured functions/aliases each call with `set +e; set +u` (`base.py:414-417`) and pipes `SUDO_PASSWORD` transformations through `_prepare_command` (`base.py:951-955`). Convenient, but it treats the shell as trusted; newt's OCAP argv-engine deliberately does not. Port the *seam*, not the trust model.

5. **In-process cron running full agent turns inside the gateway.** Thread pools + contextvars + loop-threadsafe delivery inside one process produced the shutdown deadlock class (`run.py:19834-19845`) and lock-file tick guards (`scheduler.py:7-9`). newt already has the right substrate — systemd timers / wyvern headless runs writing to the recall store — where the OS supervises isolation; only the wake-gate and delivery-target *conventions* are worth taking.

6. **Cross-platform continuity as marketed.** There is no unified session; it's per-(platform,chat) keys (`session.py:856`) plus mirroring and search. Don't chase "handoff" as a feature — hermes itself ships the honest version (recall + mirror), which newt effectively has.

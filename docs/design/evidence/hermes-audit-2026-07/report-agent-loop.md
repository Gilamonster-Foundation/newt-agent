# hermes-agent core loop survey (vs. newt-agent)

## Scale (a finding in itself)

`run_agent.py` = 6,013 lines / 269KB; `cli.py` = 16,184 lines / 743KB; `gateway/run.py` = 20,526 lines; `agent/conversation_loop.py` = 5,294 lines, of which `run_conversation()` is a **single ~4,700-line function** (lines 518–5290). The `agent/` dir holds ~110 extracted modules, and comments admit the mid-flight refactor: "god-file decomposition Phase 1 step 4" (conversation_loop.py:5272), "Extracted from run_agent.py" headers everywhere (iteration_budget.py:3, turn_retry_state.py:12-16). This is a project paying down monolith debt while shipping; the extraction pattern (module-level function taking `agent` as first arg, thin forwarder kept for test-patch compat) is visible in tool_executor.py:1-11.

## How a turn executes

1. **Prologue** — `build_turn_context()` (turn_context.py) does once-per-turn setup: nudge-counter hydration from persisted history (turn_context.py:278-286), budget reset (`IterationBudget(max_iterations)`, :258), system-prompt restore-or-build (:329-333), user-message append.
2. **Outer loop** — `while (api_call_count < agent.max_iterations and agent.iteration_budget.remaining > 0) or agent._budget_grace_call` (conversation_loop.py:633). Cap default **90** for the parent, **50** per subagent, each subagent independent so total can exceed the parent cap (iteration_budget.py:20-27; agent_init.py:271). `execute_code`-only rounds are **refunded** (conversation_loop.py:4708-4713). Deliberate design: **no intermediate budget-pressure warnings** — "they caused models to 'give up' prematurely on complex tasks (#7915)"; instead one grace call at exhaustion, then `handle_max_iterations` appends a user message requesting a final no-tools summary (agent_init.py:624-631; chat_completion_helpers.py:1500-1509).
3. **Per iteration** the full `api_messages` list is rebuilt from scratch: sanitize corrupted tool_call args, repair role-alternation violations (:751-780), inject ephemeral context, apply cache markers, strip thinking-only turns, then call.
4. **Inner retry loop** — `while retry_count < max_retries` (:1095), default **3** (agent_init.py:1490-1497), with jittered decorrelated exponential backoff (retry_utils.py:28-66).
5. **Streaming always preferred, even with no consumer** — "Streaming gives us fine-grained health checking (90s stale-stream detection, 60s read timeout) that the non-streaming path lacks… subagents can hang indefinitely when the provider keeps the connection alive with SSE pings" (conversation_loop.py:1252-1262); the non-stream path mirrors a wall-clock stale detector (chat_completion_helpers.py:310-340).

## Error/retry handling

Centralized taxonomy: `FailoverReason` enum with ~25 categories mapping error → recovery action (retry / rotate credential / provider fallback / compress / shrink image / abort) (error_classifier.py:24-73, `classify_api_error` at :515). Per-attempt one-shot recovery guards were collapsed from "~16 bare `*_attempted` locals threaded through its 2,400-line body" into a `TurnRetryState` dataclass with `restart_with_*` signals the loop reads back (turn_retry_state.py:12-40). Failover is a chain: credential-pool rotation with a per-turn same-entry refresh cap (conversation_loop.py:612-617, #26080), then `_try_activate_fallback()` to another provider, resyncing the system message (`_sync_failover_system_message`). Provider-specific rate policies exist (Z.AI 429-code-1305 long backoff, retry_utils.py:80-129; Nous portal cross-session rate-guard that skips the call entirely, conversation_loop.py:1096-1144).

## Provider abstraction

Internal lingua franca is **OpenAI chat-completions dicts**; wire differences are handled at three layers:
- **Transports** (`agent/transports/`): `ProviderTransport` ABC — `convert_messages → convert_tools → build_kwargs → normalize_response(→NormalizedResponse)`; explicitly does *not* own client construction, streaming, credentials, or retry — "Those stay on AIAgent" (transports/base.py:1-8). Registry with lazy discovery (transports/__init__.py:26-46). Modes: chat_completions, anthropic, bedrock, codex (Responses), codex_app_server (whole-turn handoff to a subprocess, conversation_loop.py:619-631).
- **ProviderProfile**: declarative dataclass of auth/endpoint/quirks — "The transport reads this instead of receiving 20+ boolean flags" (providers/base.py:1-11).
- **But the loop still leaks**: reasoning-echo pads for Kimi/DeepSeek/MiMo (run_agent.py:5456-5491), Qwen-portal message rewriting (:5237), Copilot `x-initiator` billing header (conversation_loop.py:1161-1168), llama.cpp grammar recovery, Moonshot `reasoning_content`. The abstraction is aspirational; string-matched quirk branches remain the working reality.

## System prompt & prompt-cache discipline (their strongest area)

- Built **once per session** in three tiers (stable / context / volatile), cached on `_cached_system_prompt`, "Hermes never re-renders parts of this string mid-session — that's the only way to keep upstream prompt caches warm" (system_prompt.py:113-130).
- **Persisted to SQLite and restored verbatim** on continuation (critical for gateway, which builds a fresh agent per turn), with a four-state diagnostic (missing/null/empty/present) and WARNING-level logs whenever a prefix-cache miss will occur (conversation_loop.py:277-398), plus a staleness check on Model/Provider identity lines (:401-422).
- **Ephemeral content never touches the system prompt**: memory prefetch and plugin context are appended to the API-call-time *copy* of the current user message only (:786-802, comment at :827-841).
- **Byte-stability normalization**: strip content whitespace and canonicalize tool-call JSON args (`sort_keys`, compact separators) "for bit-perfect prefixes across turns, which enables KV cache reuse on local inference servers (llama.cpp, vLLM, Ollama)" (:910-941).
- Anthropic markers: single `system_and_3` layout — system + last 3 messages, 4 breakpoints — with a layout-aware carrier predicate so breakpoints aren't wasted on messages the envelope layout ignores (prompt_caching.py:1-73). (The "~75% cost reduction" is a docstring claim, not measured in code.)

## Deciding "done" — a recovery ladder, then verification gates

No tool calls ≠ done. The final-response branch (conversation_loop.py:4768) runs: (1) partial-stream recovery — already-streamed text becomes the answer (:4781-4807); (2) prior-turn content fallback when the last tools were all housekeeping (:4819-4833); (3) **post-tool empty-response nudge** — synthetic `assistant("(empty)") + user(nudge)` pair preserving role alternation, one shot (:4835-4900, #9400); (4) thinking-only **prefill continuation** ≤2 (:4902-4934); (5) empty retry ≤3 (:4936-4963); (6) provider fallback; (7) `"(empty)"` terminal flagged `_empty_terminal_sentinel` so it never persists (:5007-5013). Then an **intermediate-ack detector** ("I'll now do X" with no tool calls → system "Continue now" message, ≤2) (:5055-5081). Then two verification gates before accepting the answer:

- **Verify-on-stop** (verification_stop.py): policy-only module reading a **passive evidence ledger** (verification_evidence.py, SQLite) that the terminal tool populates by classifying commands against project `verifyCommands` with pass/fail + output summary (terminal_tool.py:2746; verification_evidence.py:383-428); file tools mark the workspace edited (file_tools.py:1615). If the turn edited code paths (doc/prose extensions filtered, verification_stop.py:24-53) without fresh *passing* evidence, a synthetic user nudge quoting the last command/output is injected, ≤2 attempts, both messages flagged synthetic and stripped from persistence to avoid assistant→assistant adjacency on resume (conversation_loop.py:5110-5155, #55733). Surface-aware default: ON for CLI/TUI/programmatic, OFF for Telegram/Discord-style surfaces, default-deny for unknown surfaces (verification_stop.py:86-100).
- A pluggable `pre_verify` hook gate (:5157-5206).

Every exit path sets a `_turn_exit_reason` diagnostic string (`text_response(finish_reason=…)`, `budget_exhausted`, `guardrail_halt`, `empty_response_exhausted`, …) carried into `finalize_turn`.

## Interrupt and steer

- `interrupt(msg)`: thread-safe flag + per-thread tool-abort signals fanned out to concurrent tool-worker tids and recursively to child subagents (run_agent.py:2619-2685); checked at loop top (:638 in conversation_loop), in tool-executor preflight (tool_executor.py:320-333), and during retry backoff.
- `steer(text)`: **non-interrupting mid-turn redirect** — text is stashed under a lock and drained either after the tool batch (appended to the last tool result) or in a **pre-API-call drain** so a steer sent while the model was thinking lands on *this* iteration, injected into the last tool-role message to preserve role alternation (run_agent.py:2720-2770; conversation_loop.py:694-743). A static `STEER_CHANNEL_NOTE` in the stable system-prompt tier tells the model steers arrive inside tool results (system_prompt.py:208-211). A hard interrupt drops pending steers (run_agent.py:2711-2718).

## Other wired-in mechanisms worth noting

- **Parallel tool dispatch**: concurrent path only for batches that look independent — read-only tools always; path-scoped file ops only when targets don't overlap (run_agent.py:5631-5650) — paired with system-prompt guidance telling the model to batch (system_prompt.py:176-185).
- **Tool-result 3-level budget**: per-tool cap → per-result spill to `/tmp/hermes-results/{id}.txt` with preview+path (model `read_file`s it back) → per-turn 200K-char aggregate budget spilling largest results (tool_result_storage.py:1-23), budget scaled to the active model's context window (tool_executor.py:54-60, #23767).
- **Crash-resilient transcript**: the assistant tool-call message is flushed to SQLite *before* tools execute, so a destructive tool that kills the process leaves a resumable transcript (conversation_loop.py:4644-4656).
- **Compression**: trigger at 50% of effective window (context_compressor.py:993) using **API-reported prompt_tokens** (not estimates; completion tokens excluded because reasoning inflates them, #12026) (conversation_loop.py:4715-4751), plus a pre-API pressure recheck for the "one turn grew by huge tool results" case (:978-994), with estimates including tool schemas (20-30K tokens at 50+ tools, #14695).
- **Nudges as background work**: memory review every N user turns and skill-creation review every 10 tool iterations run *after* the response is delivered via `_spawn_background_review` "so it never competes with the user's task for model attention" (turn_context.py:306-314; agent_init.py:1423; turn_finalizer.py:454-478).
- **Subagents**: `delegate_task` from the top-level model is always background (results re-enter as new messages); orchestrator subagents stay synchronous (run_agent.py:5654-5684).

## Candidate learnings for newt

1. **Prefix-cache discipline as a named, enforced invariant.** Mechanism: system prompt built once per session, persisted (SQLite) and restored byte-identical on resume with logged four-state diagnostics on every miss cause; ephemeral context injected only into the API-time copy of the current user message; tool-call JSON canonicalized (sorted keys, compact) and content stripped for bit-perfect prefixes (conversation_loop.py:277-398, 786-846, 910-941). Plug-in point: newt-core/src/agentic request builder + session resume path; newt's structural prune/compression pipeline must be audited to never rewrite the retained prefix. Payoff: real cost/latency wins on Anthropic caching *and* KV-cache reuse on local ollama/llama.cpp — directly serves newt's local-first thesis. This is the single highest-value import.
2. **Evidence-gated stop (verify-on-stop).** Mechanism: passive SQLite ledger of classified verification commands (pass/fail, canonical command, output summary) written by the terminal tool; a policy-only stop gate that fires a bounded (≤2), non-persisted synthetic nudge only when code (not docs) was edited without fresh passing evidence, quoting the last failing output (verification_evidence.py:383-428; verification_stop.py:245-310; conversation_loop.py:5110-5155). Plug-in: newt already has the pieces — nudge classifier TOMLs, LanguagePacks (which know verify commands → three-Cs compliant data), and harness-side verification in crew; this brings evidence-gating to the *single-agent* loop. Payoff: kills premature "done" claims; measurable with newt's Fisher-exact eval gates.
3. **Typed error taxonomy + one-shot recovery guards.** Mechanism: `FailoverReason` enum → recovery-action mapping consulted for every API failure, and a per-attempt `TurnRetryState` struct of one-shot booleans + restart signals replacing scattered locals (error_classifier.py:24-73; turn_retry_state.py). Plug-in: newt's provider retry code; Rust enums make this cleaner than hermes' version. Payoff: legible, testable recovery; prevents duplicate recovery firing.
4. **Mid-turn non-interrupting steer channel.** Mechanism: stash under lock; drain into the last tool-result message (post-batch or pre-API) preserving role alternation and the cache prefix; static system-prompt note announcing the channel; hard interrupt discards pending steers (run_agent.py:2720-2770; conversation_loop.py:694-743). Plug-in: newt TUI keybinding + agentic loop drain points — fully compatible with the plain-scroller decision (it's a queue, not a widget). Payoff: redirect without losing an in-flight tool round.
5. **Empty/thinking-only recovery ladder with non-persisted scaffolding.** Mechanism: nudge → prefill-continuation → bounded retries → provider fallback, every synthetic message flagged (`_empty_recovery_synthetic`, `_thinking_prefill`) and popped before anything durable is appended (conversation_loop.py:4835-5042, 5099-5108). Plug-in: newt's stall classifier already detects these states; the ladder adds *recovery* order and the flag-and-strip transcript hygiene. Payoff: local models (newt's bread and butter) are exactly the ones that go empty after tool results.
6. **Always-stream for liveness, even headless.** Mechanism: streaming path used regardless of consumers because it enables 90s stale-stream / 60s read-timeout detection; non-stream fallback gets a mirrored wall-clock watchdog (conversation_loop.py:1252-1262). Plug-in: newt headless/crew workers. Payoff: no silent SSE-ping hangs in overnight sweeps.
7. **Flush-before-destructive-tool persistence** (conversation_loop.py:4644-4656) and **`_turn_exit_reason` on every exit path** (:610 et passim) — both trivial to add to newt's session store and eval autopsy tooling respectively.
8. **No mid-flight budget pressure warnings** (#7915, agent_init.py:624-631): independent evidence for newt's existing grace-round design — do not add "you're running low on rounds" nudges; hermes tried and reverted because models gave up early.

## Avoid replicating

1. **The monolith.** A 4,700-line single-function turn loop, 6K/16K/20K-line files, and a multi-phase "god-file decomposition" the authors are still paying for (conversation_loop.py:5272; turn_retry_state.py:12-16 describing "~16 bare locals threaded through its 2,400-line body"). newt's small-crate, 88%-coverage discipline is the asset hermes is trying to retrofit.
2. **Inline per-provider quirk branches.** Despite transports + declarative profiles, the loop still hosts dozens of string-matched provider special cases (Kimi/DeepSeek/MiMo reasoning pads run_agent.py:5456-5491, Qwen portal :5237, Copilot header conversation_loop.py:1161-1168, Z.AI backoff retry_utils.py:80-129). Newt's model-cards + family-defaults data files are the correct three-Cs answer; importing quirk branches would be regression.
3. **Fail-open `except Exception: pass` as default posture.** Pervasive (e.g. conversation_loop.py:560-561, 1141-1144, every hook invocation). Rational for a chat product; incompatible with newt's OCAP/caveat model where authority-relevant failures must fail closed.
4. **Budget refunds and 90-round ceilings.** Refunding `execute_code` rounds (conversation_loop.py:4708-4713) creates a category of "free" iterations that's hard to reason about in evals; newt's 40 + progress-aware grace is tighter and already A/B-gated.
5. **Display state woven through the executor.** Spinners, cute tool messages, output-muting flags (`_mute_post_response`, `_last_content_tools_all_housekeeping`) live inside dispatch and the done-decision (tool_executor.py:24-31; conversation_loop.py:4596-4614) — exactly the coupling newt's plain-scroller decision exists to prevent.
6. **Env-var session-context plumbing** for behavior gates (`HERMES_SESSION_PLATFORM`/`HERMES_VERIFY_ON_STOP`, verification_stop.py:103-170): global mutable process state deciding policy; newt should express the same surface-awareness through its config/caveat lattice.

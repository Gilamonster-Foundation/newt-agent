# Hermes-Agent Subagent/Delegation Survey vs newt-agent

## The spawn mechanism

Hermes's delegation is a single model-facing tool, `delegate_task`, defined in `tools/delegate_tool.py` (3,445 lines — one file owns the whole feature). Entry point `delegate_task(goal, context, tasks, max_iterations, role, background, parent_agent)` at `tools/delegate_tool.py:2342`. Two modes: single (`goal`+`context`) or batch (`tasks=[{goal, context, role}, ...]`), capped at `delegation.max_concurrent_children` (default 3, floor 1, no ceiling, one-time cost warning >10; `tools/delegate_tool.py:354-392`). A `role` param (`leaf` default / `orchestrator`) controls nesting. The toolset is registered as `"delegation": {"tools": ["delegate_task"]}` at `toolsets.py:245-249`.

## What "isolation" actually means

**Not process, not container, not directory.** A child is an in-process `AIAgent` instance built on the parent's main thread (`_build_child_agent`, `tools/delegate_tool.py:1044-1397`) and run on a `DaemonThreadPoolExecutor` worker thread (`tools/delegate_tool.py:2537-2548`). Isolation is:

- **Context isolation**: fresh conversation, no parent history; a focused ephemeral system prompt built from goal+context (`_build_child_system_prompt`, `tools/delegate_tool.py:661-736`); `skip_context_files=True, skip_memory=True` (`tools/delegate_tool.py:1319-1320`). The docstring is explicit: "The parent's context only sees the delegation call and the summary result, never the child's intermediate tool calls" (`tools/delegate_tool.py:15-16`).
- **Session isolation**: own `task_id` = `subagent_id` (`sa-{i}-{uuid8}`), which keys its own terminal session and file-ops cache (`tools/delegate_tool.py:1874-1880`).
- **Capability attenuation (weak, list-based)**: `DELEGATE_BLOCKED_TOOLS` frozenset strips `delegate_task, clarify, memory, send_message, execute_code, cronjob` (`tools/delegate_tool.py:45-54`); child toolsets are the parent's toolsets intersected/stripped — "subagent must not gain tools the parent lacks" (`tools/delegate_tool.py:1119-1135`).
- **NOT filesystem isolation**: children share the parent's cwd and filesystem. The child prompt merely injects a "WORKSPACE PATH" hint (`tools/delegate_tool.py:685-690`, `_resolve_workspace_hint:739-763`). Because siblings can collide, hermes bolted on a process-wide `FileStateRegistry` (`tools/file_state.py:1-31`) tracking per-task read stamps and last-writer, plus a post-run "sibling wrote files you already read — re-read before editing" reminder in the parent's result (`tools/delegate_tool.py:2152-2157`).

Container isolation exists only in the research runners: `mini_swe_runner.py:117-150` picks local/docker/modal backends per task, and `batch_runner.py:262-312` registers per-prompt docker/modal/singularity/daytona image overrides via `register_task_env_overrides(task_id, ...)`.

## Results, budgets, failure, cleanup

**Return path (sync)**: parent blocks; results come back as one JSON blob with per-task `{status, summary, api_calls, duration_seconds, model, exit_reason, tokens, tool_trace}` (`tools/delegate_tool.py:2108-2142`). `tool_trace` is a compact per-call ledger (tool name, args_bytes, result_bytes, ok/error) rebuilt from the child's message list (`tools/delegate_tool.py:2059-2093`) — the parent gets an auditable skeleton without the transcript.

**Return path (background)**: `background=true` dispatches the whole batch as ONE unit onto a module-level daemon executor (`tools/async_delegation.py:311-423`); completion pushes a rich event onto the shared `process_registry.completion_queue`, which the CLI/gateway drain and forge as a *new turn when the agent is idle* — deliberately never spliced mid-turn, preserving message alternation and prompt cache ("hard invariant: never mutate past context", `tools/async_delegation.py:9-29`). At capacity, async dispatch is **rejected, not queued**, falling back to synchronous execution (`tools/delegate_tool.py:2868-2885`; rationale at `tools/async_delegation.py:154-157`: "a runaway model can't pile up unbounded background work"). Stateless HTTP sessions also degrade to sync because there's no channel to deliver a detached result (`tools/delegate_tool.py:2770-2796`).

**Budgets**: per-child iteration cap `delegation.max_iterations` default 50 (`tools/delegate_tool.py:586`); model-supplied `max_iterations` is *ignored* — config is authoritative (`tools/delegate_tool.py:2407-2418`). Wall-clock timeout default **None** — deliberately removed because a blanket cap killed legitimately-slow children; stuck-child detection moved to a heartbeat staleness monitor instead (`tools/delegate_tool.py:425-441`). The heartbeat thread touches parent activity every 30s with the child's current tool/iteration, and *stops touching* after 15 idle / 40 in-tool stale cycles so the gateway inactivity timeout can reap a wedged child (`tools/delegate_tool.py:605-615, 1767-1834`). Child token spend is folded into the parent's session cost (`_children_cost_total` rollup, `tools/delegate_tool.py:2694-2750`).

**Summary back-pressure**: `_apply_summary_budget` caps each child summary at min(static `max_summary_chars`=24,000, dynamic per-summary budget = parent's *remaining* context headroom × 0.5 ÷ batch size × 4 chars/token) (`tools/delegate_tool.py:1624-1716`). Over-budget summaries keep a 75% head / 25% tail window snapped to line boundaries, spill the full text to `cache/delegation/subagent-summary-*.txt`, and append a footer with the exact `read_file offset=` to page the omitted middle (`tools/delegate_tool.py:1569-1621`).

**Nesting**: `MAX_DEPTH = 1` — flat by default (`tools/delegate_tool.py:125`). Nesting requires BOTH raising `delegation.max_spawn_depth` (floor 1, no ceiling; `tools/delegate_tool.py:467-503`) AND passing `role='orchestrator'`, which re-adds the stripped `delegation` toolset (`tools/delegate_tool.py:1137-1142`) and appends a WHEN/WHEN-NOT-to-delegate prompt block whose depth note is "literal truth grounded in the passed config so the LLM doesn't confabulate nesting capabilities" (`tools/delegate_tool.py:672-735`). A global `orchestrator_enabled` kill switch degrades everything to leaf (`tools/delegate_tool.py:506-520`).

**Failure handling**: children can't prompt the user; a thread-local approval callback auto-denies dangerous commands by default (opt-in auto-approve), specifically to avoid an `input()` deadlock against the parent's prompt_toolkit TUI (`tools/delegate_tool.py:57-112`, installed via executor initializer at 1894-1903). Timeouts with 0 API calls dump a diagnostic including the worker thread's Python stack (#14726; `tools/delegate_tool.py:1949-1975`). The empty-response sentinel `"(empty)"` is treated as failure, not success (`tools/delegate_tool.py:2042-2057`). Parent interrupt propagates via `_active_children` and a poll-with-0.5s-timeout join loop that abandons wedged futures instead of blocking forever (`tools/delegate_tool.py:2550-2596`).

**Reaping/observability**: module-level `_active_subagents` registry + `set_spawn_paused()` operator kill switch — the TUI can freeze *new* fan-out without killing running children (`tools/delegate_tool.py:143-215, 2368-2375`); `interrupt_all()` on `/stop`/shutdown so "a dangling background subagent can't keep burning tokens with no one listening" (`tools/async_delegation.py:494-519`). No thread is ever hard-killed (Python can't); daemon threads ensure process exit isn't blocked (`tools/async_delegation.py:60-62`). Lifecycle hooks `subagent_start`/`subagent_stop` fire for plugins, serialized on the parent thread (`tools/delegate_tool.py:1382-1395, 2683-2728`).

## batch_runner.py and mini_swe_runner.py

These are **not** the delegation system — they're offline trajectory-generation harnesses (hermes is Nous Research's agent; the output format is SFT `from/value` pairs). `batch_runner.py` (1,321 lines): loads a JSONL dataset, shards into batches, runs batches across a `multiprocessing.Pool` (`batch_runner.py:918-931`), each prompt getting a fresh `AIAgent` with toolsets *sampled from a distribution* (`sample_toolsets_from_distribution`, `batch_runner.py:318`), `skip_context_files/skip_memory` so trajectories aren't polluted (`batch_runner.py:344-345`), per-prompt container images, checkpointing plus **content-based resume** (scan existing batch files and match completed prompts by text, not index — `batch_runner.py:821-853`), and tool-stat schemas normalized over ALL possible tools so Parquet/HF loading never schema-mismatches (`batch_runner.py:61-98`). `mini_swe_runner.py` (732 lines) is a deliberately minimal bash-only agent (one terminal tool) over the same environment backends; `run_batch` is *sequential* with immediate flush-per-line JSONL (`mini_swe_runner.py:593-620`). Orchestration here is process-pool + checkpoint files — no message bus, no shared state beyond the filesystem.

## Scale note

Single-file gravity is real: `delegate_tool.py` 3,445 lines, `run_agent.py` 6,013, `cli.py` 16,184, `gateway/run.py` 20,526. The delegation module's history is archaeology-in-comments (issue numbers #9126, #14726, #16816, #20558, #49148 inline) — every guard exists because something bled. That's the honest signal: thread-based in-process delegation over a shared filesystem generates a long tail of patches (approval-callback deadlocks, global-toolset-name corruption at `tools/delegate_tool.py:2472-2512`, file-state races) that newt's worktree+process model avoids structurally.

## Candidate learnings for newt

1. **Context-headroom-scaled child summary caps with head+tail spill and a paging pointer** (`_apply_summary_budget` / `_trim_summary_with_footer`, `tools/delegate_tool.py:1569-1716`). Mechanism: cap = min(static ceiling, parent's remaining context × fraction ÷ fan-out), spill full text to a grep-able file, footer says exactly how to page the omitted middle. Plug-in: newt already has tool_offload (head+tail cap + spill store with memory_fetch) — extend it so the *crew/#948 subagent return path* is budgeted against the parent's live headroom divided by the number of concurrent returns, not a fixed constant. Payoff: batch fan-out can never blow the parent's window (hermes's #9126 was exactly a fan-out → compression/429 death spiral).

2. **Reject-not-queue at background capacity, with sync fallback** (`tools/async_delegation.py:154-157, 183-198`; `tools/delegate_tool.py:2868-2885`). Mechanism: capacity check + record insert under one lock; over-cap dispatch fails fast and the work runs inline with an explanatory note. Plug-in: #948's tool and any crew async surface. Payoff: a looping model can't accumulate unbounded background jobs — the failure mode is visible and self-limiting.

3. **Completion re-enters as a fresh turn on the existing completion queue, never spliced** (`tools/async_delegation.py:9-29`), carrying a self-contained task-source block (original goal, context, dispatch time) because "the parent may be deep in unrelated context and won't remember why the subagent existed" (`tools/async_delegation.py:24-29`). Plug-in: if newt ever adds async crew results, deliver via newt's existing scheduled/plan-ledger rail as a new message; include the dispatch-time spec verbatim. Payoff: prompt-cache integrity + the parent can re-decide relevance.

4. **Progress-based staleness instead of wall-clock timeouts** (`tools/delegate_tool.py:425-441, 1767-1834`). Mechanism: no default timeout; a heartbeat relays (current tool, iteration) upward and counts stale cycles with *different thresholds for idle vs in-tool*; staleness stops the heartbeat so the outer supervisor reaps. This is the same shape as newt's progress-aware grace rounds, applied one level up. Plug-in: crew role supervision in newt-scheduler — reap on no-progress, not on elapsed time. Payoff: slow-but-working reviewers survive; wedged ones die.

5. **Depth-grounded, non-confabulating orchestrator prompt** (`tools/delegate_tool.py:705-735`): the WHEN/WHEN-NOT block plus "you are at depth N, cap is M, your children MUST be leaves" computed from actual config. Plug-in: #948's tool description / crew role preambles — state the child's *actual* attenuated authority (its met-down caveat set) in its prompt. Payoff: fewer wasted rounds where a child attempts capabilities it doesn't have. Fits Three Cs if the WHEN/WHEN-NOT text lives in a workflow-steer-style TOML rather than hardcoded strings (hermes hardcodes it — copy the idea, not the placement).

6. **Structured tool_trace + cost rollup in the return payload** (`tools/delegate_tool.py:2059-2142, 2694-2750`). Mechanism: per-call {tool, args_bytes, result_bytes, ok/error} skeleton plus child token/cost totals folded into the parent's session accounting. Plug-in: #948's result struct and crew branch reports. Payoff: the parent (and newt's eval graders) can audit what a child *did* without ingesting its transcript; subagent-heavy runs stop under-reporting cost.

7. **0-API-call timeout diagnostics with worker stack dump** (`tools/delegate_tool.py:1949-1975, 1400+`). Cheap, high-leverage failure forensics: when a child dies before its first LLM call, dump what it was doing. Plug-in: newt crew spawn path (worktree setup, model resolution) — write a diagnostic file on pre-first-round failure. Payoff: "black box hang" bugs become one-look fixes.

8. **Content-based resume in batch sweeps** (`batch_runner.py:732-853`): identify completed work by prompt *content* scanned from output files, not by index/checkpoint alone. Plug-in: newt's n≥5 sweep harnesses — resume by (task, seed, binary-hash) content key. Payoff: interrupted sweeps resume correctly even after dataset reordering; complements the memory note that resumes must re-pin binaries.

## Avoid replicating

1. **In-process, shared-filesystem children.** Hermes's entire `FileStateRegistry` (`tools/file_state.py`), the sibling-write reminders (`tools/delegate_tool.py:2152-2157`), the global `_last_resolved_tool_names` save/restore dance (`tools/delegate_tool.py:2472-2512`), and the approval-callback TLS deadlock fix (`tools/delegate_tool.py:57-98`) are all patches for problems newt's isolated-worktree-per-role design *doesn't have*. Worktree isolation makes an entire bug class unrepresentable; keep it for #948.

2. **Thread-based children you can't kill.** `interrupt_subagent` "does not hard-kill the worker thread (Python can't)" (`tools/delegate_tool.py:182-189`); abandoned futures and daemon threads are the mitigation (`tools/delegate_tool.py:2023-2026`). newt should spawn subagents as processes (it already does for crew) so reaping is a real kill, not a cooperative flag.

3. **Trust-the-summary landing.** Hermes's contract is "child self-reports; parent believes it" — status is `completed` merely because a non-empty summary exists (`tools/delegate_tool.py:2049-2057`). No harness-run verification, no commit gate. Newt's harness-runs-verification + commit-to-branch is strictly stronger; do not regress to prose-as-proof (this is newt's "patch not prose" law).

4. **Denylist capability attenuation.** `DELEGATE_BLOCKED_TOOLS` is a frozenset of names plus a parallel composite-toolset strip that must be kept "in lockstep" by hand (`tools/delegate_tool.py:766-783`). One forgotten name is a leak. Newt's OCAP caveat lattice (met-down authority, Lean-specced) is the correct shape; hermes demonstrates the maintenance tax of the wrong one.

5. **Unbounded config knobs on multiplicative costs.** `max_concurrent_children` and `max_spawn_depth` have floors but "no ceiling" (`tools/delegate_tool.py:358, 479-480`), guarded only by a one-time log warning. With nesting, cost is exponential in depth × width. If newt exposes #948 knobs, cap them or gate raises behind the same explicit-approval class as force-push.

6. **The 3.4K-line single-file tool (and 20K-line gateway).** `delegate_tool.py` mixes schema building, credential routing, TUI relays, heartbeats, summary budgeting, and cost accounting in one module; provider-routing edge cases (#16816, #20558 at `tools/delegate_tool.py:1203-1250`) each added inline special cases. Newt's small-crates discipline is the antidote — a subagent tool should compose newt's existing spawn/verify/land primitives, not re-implement a second agent runtime inside a tool.

7. **Duplicated orchestration stacks.** Hermes has delegate_task, the kanban dispatcher (separate env-gated toolset, `toolsets.py:260-270`), and two research runners — three parallel multi-agent mechanisms with different isolation and no shared authority model. Newt should keep crew/team and #948 on one substrate (worktree + caveat met-down + harness verification) rather than growing mode-specific runtimes.

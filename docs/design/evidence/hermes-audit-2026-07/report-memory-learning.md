# hermes-agent Memory & Learning Loop — survey vs newt

All paths relative to `hermes-agent@830165473:`.

## 1. What the loop actually is (wired-in behavior)

**Curated store on disk.** Two §-delimited plain-text files under `$HERMES_HOME/memories/`: `MEMORY.md` (agent notes, 2,200-char budget ≈ 800 tokens) and `USER.md` (user profile, 1,375 chars ≈ 500 tokens) — `tools/memory_tool.py:130`, defaults confirmed at `cli-config.yaml.example:537-544`. One `memory` tool with add/replace/remove plus an **atomic batch shape** validated against the *final* budget only, so the model can free space and add in one call instead of a multi-turn consolidate dance (`memory_tool.py:497-509`). Both files are injected into the system prompt as a **frozen snapshot** captured at session start; mid-session writes hit disk immediately but never mutate the prompt, preserving the prefix cache (`memory_tool.py:113-124,615-626`; injection at `agent/system_prompt.py:426-433`). So the total always-injected block is ~1,300 tokens ceiling, enforced in characters.

**Write triggers ("nudges").** Three real mechanisms:
- *Tool-schema exhortation*: the `memory` tool description says when to save (preferences > environment > procedures) and what to skip (`memory_tool.py:1058-1081`).
- *Turn-counted background review*: every `nudge_interval` user turns (default 10, `agent/agent_init.py:1330-1338`; counter in `agent/turn_context.py:306-314`, hydrated across `/resume` via `prior_user_turns % interval`, `turn_context.py:278-286`, issue #22357), `turn_finalizer.py:472-478` spawns — **after the reply is delivered, on a daemon thread** — a forked `AIAgent` that replays the conversation snapshot and is asked `_MEMORY_REVIEW_PROMPT` ("Review the conversation above… If nothing is worth saving, say 'Nothing to save.'", `agent/background_review.py:160-168`). A parallel skill review fires every 15 tool iterations (`agent_init.py:1423-1426`). The fork is heavily fenced: tool whitelist limited to memory/skill toolsets (`background_review.py:786-802`), `skip_memory=True` so it can't leak the harness prompt into external providers (`background_review.py:665-697`), `_persist_disabled=True` so its synthetic prompt can't be re-read next turn as a standing instruction — the documented "curator-takeover" failure where the agent *became* the curator (`background_review.py:712-727`), compression disabled (`background_review.py:766-776`), and it inherits the parent's cached system prompt for prompt-cache parity, with a **measured** ~26% end-to-end cost reduction cited (PR #17276, `background_review.py:740-748`).
- *Anti-thrash countermeasures*: success responses are deliberately terminal ("do not repeat it") because dumping entries back caused observed 5x redundant repeats (`memory_tool.py:645-662`); a per-turn cap of 3 failed consolidations degrades to "stop retrying, answer the user" so memory can't eat the turn budget (#42405, `memory_tool.py:127-166`).

**Store hygiene.** Injection/exfil scanning of entries at write time *and* at snapshot load with `[BLOCKED: …]` placeholders (poisoned entries stay visible on disk for the user to delete) — `memory_tool.py:168-241`. External-drift detection (round-trip mismatch or oversized entry) refuses the write and snapshots a `.bak` instead of silently truncating a hand-edited file (#26045, `memory_tool.py:704-757`). Atomic temp-file+rename writes; flock for RMW (`memory_tool.py:759-788`).

## 2. Cross-session recall

`session_search` (`tools/session_search_tool.py`) over the SQLite session DB with a plain FTS5 index (content + tool_name + tool_calls, trigger-maintained — `hermes_state.py:813-836`; a **trigram** FTS5 twin for CJK substring search, `hermes_state.py:838-847`). Four arg-inferred shapes: DISCOVERY (FTS5, dedupe by session lineage, each hit returns snippet + ±5-message window + **bookend_start/bookend_end** — first/last 3 user+assistant messages, i.e. goal → match → resolution), SCROLL (anchored ±window paging by message id), READ, BROWSE (`session_search_tool.py:4-30,771-806`). Two ranking fixes worth stealing: cron/automation sessions are *demoted, not excluded* because their repetitive vocabulary dominated BM25 and caused "recall blindness" (#19434, `session_search_tool.py:42-52`), and a 300-row scan-before-dedupe budget so interactive hits buried under cron walls still surface (`session_search_tool.py:54-58`).

**Important negative finding:** the "LLM-summarized recall" is *retired*, not current. The module header states "No LLM calls anywhere — every shape returns actual messages from the DB"; PR #20238's fast/summary dual mode was deliberately collapsed into the single no-LLM shape (`session_search_tool.py:23-30`). Hermes converged on exactly the position newt settled in 2026-06: deterministic FTS5, raw messages, model does its own synthesis.

## 3. Honcho user-modeling plugin (opt-in)

`plugins/memory/honcho/` (~4,900 LOC across 6 files) is one of **eight** external providers (byterover, hindsight, holographic, honcho, mem0, openviking, retaindb, supermemory), one active at a time (`agent/memory_manager.py:374-397`). It ships every user/assistant turn to the hosted Honcho backend (`__init__.py:1214-1248`) and injects two layers pre-turn: cached `peer.context()` (session summary, "user representation", peer card) plus a **dialectic supplement** — an LLM running *on Honcho's servers* answering "what do you know about this user relevant to <next user message>" (`__init__.py:634-777`; `session.py:601-664`, capped 600 chars). The injected block is fenced `<memory-context>` with a "NOT new user input" system note, appended to the current user message at API-call time only — never persisted (`memory_manager.py:336-350`; `conversation_loop.py:788-802`). Around this sits substantial defensive machinery: a stateful **streaming scrubber** because models echo the fence tags across chunk boundaries (`memory_manager.py:171-333`), cadence/backoff/staleness state (turn-counted context and dialectic cadences, empty-streak backoff, stale-result discard multiplier, `__init__.py:223-239,744-760`), trivial-prompt gating, cron-context hard skip (#4053), and fail-open background init so a down backend can't block startup (`__init__.py:352-425`). Default `contextTokens` is **None = uncapped** injection (`client.py:126-134`). `sync_all`/`queue_prefetch_all` run on a single-worker daemon executor after a misconfigured provider blocked a turn for ~298s (`memory_manager.py:558-614`).

## 4. Measured or vibes?

Engineering behavior is densely regression-tested (nudge-counter hydration, interrupted sync, drift guard, session isolation — `tests/run_agent/test_memory_nudge_counter_hydration.py`, `tests/test_background_review_session_isolation.py`, etc.), and the prompt-cache economics of the review fork were measured (26% cost claim, `background_review.py:745`). But **memory quality itself is unevaluated**: no recall-precision benchmark, no A/B of nudge cadence, no grader for "did saved memories help later sessions" — the closest artifacts are usage dashboards (`agent/insights.py`) and a lexical-overlap "learning graph" for the desktop UI (`agent/learning_graph.py:1-13`). The do-not-capture blocklists in `_SKILL_REVIEW_PROMPT` (`background_review.py:252-270`) are scar tissue from unmeasured over-saving: "negative claims about tools… harden into refusals the agent cites against itself for months." Doc drift exists: `flush_min_turns` is documented at `cli-config.yaml.example:549` but implemented nowhere in the tree (grep confirms the example file is its only occurrence). Single-file scale: `cli.py` 16,184 lines, `run_agent.py` 6,013, `gateway/run.py` 20,526.

## Candidate learnings for newt

1. **Post-response background self-review on a turn cadence** — the one structural thing newt's loop lacks. Mechanism: user-turn counter (default 10) → after the reply lands, fork a review call over the transcript with a *whitelisted* tool surface (notes/experience-store write only), persistence-isolated, asked a short "anything durable to save?" prompt (`turn_context.py:306-314`, `turn_finalizer.py:472-478`, `background_review.py:660-810`). Plug-in point: newt's agent loop end-of-turn path, as a crew-style single-call subagent (natural fit for issue #948's "subagent in a worktree" lightweight tool); caveat lattice already gives the attenuation hermes hand-rolls with thread whitelists. Payoff: NOTES.md/experience entries get written *during* long sessions instead of only when the model spontaneously remembers; hermes' isolation bugs (#curator-takeover, #38727 compression race) are a pre-paid map of the failure modes. Gate adoption through newt's eval discipline — hermes never measured whether cadence-10 beats cadence-0.
2. **Hard char budget + atomic batch consolidation + terminal success responses** for any always-injected store. The budget forces curation; batch-validate-against-final-state kills the multi-round consolidation dance; terminal responses and the 3-failure cap kill write-thrash (`memory_tool.py:497-602,127-166,645-662`). Plug-in: newt's experience store / any future NOTES auto-curation. Payoff: bounded prompt cost forever, no runaway memory-tool loops — both failure modes hermes hit in production (#42405).
3. **Frozen-snapshot injection** (writes durable immediately, prompt stable until next session, `memory_tool.py:113-124`) — directly compatible with newt's prompt-caching concerns; trivially adoptable convention.
4. **Recall-ranking fixes**: demote (don't exclude) automation/cron/crew-generated sessions in FTS ranking, scan wide before lineage-dedupe (`session_search_tool.py:42-58`), and return **bookends** (first/last 3 messages) with each hit so the model reconstructs goal→match→resolution without paying for transcripts (`session_search_tool.py:756-806`). Plug-in: newt's FTS5 recall directly — crew/panel runs will pollute BM25 exactly like hermes' cron sessions did (#19434). Cheap, deterministic, evaluable.
5. **Two-budget split: operator profile vs agent notes** (`USER.md` 500 tokens vs `MEMORY.md` 800). The *useful* kernel of "user modeling" without any cloud service: a small, user-visible, plain-text, separately-budgeted "who the operator is / how they want me to behave" block. Fits newt's Three Cs as a droppable data file.
6. **Provider-grade write hygiene for agent-writable files**: threat-scan at write and at load with visible `[BLOCKED]` placeholders, and the round-trip drift guard + `.bak` before any full-file rewrite (`memory_tool.py:78-241,704-757`). Plug-in: wherever newt lets the model rewrite NOTES.md; prevents silent clobbering of hand edits — an operator-trust property aligned with newt's authority model.
7. **On-pre-compress extraction hook** — before the compression pipeline discards messages, give the memory layer one shot to pull durable facts into the compression prompt (`memory_provider.py:220-230`, `conversation_compression.py:619`). Newt has structural prune + LLM compression but no "last call for durable facts" tap on that path.

## Avoid replicating

1. **Honcho-style hosted dialectic user modeling.** Every turn ships off-box to a third-party API (`honcho/__init__.py:1214-1248`), the injected "representation" is uncapped by default (`client.py:126-134`), and the value is entirely unmeasured — while the cost is a ~1,400-line provider whose bulk is cadence/backoff/staleness/fail-open plumbing for a network dependency. Violates newt's local-first stance and buys nothing FTS5 recall + a 500-token profile file doesn't.
2. **Per-turn recall injection into the user message + fence-scrubbing arms race.** Appending `<memory-context>` to user content forced a sanitizer, a note-regex, *and* a stateful streaming scrubber because models echo the fences (`memory_manager.py:152-333`). Newt's scratchpad/system-side context placement avoids the whole bug class; don't import it.
3. **"Be ACTIVE — most sessions produce at least one skill update… a pass that does nothing is a missed learning opportunity"** (`background_review.py:170-175`). A write-bias prior with no eval behind it; hermes then needed long do-not-capture blocklists (`background_review.py:252-270`) to fight self-poisoning ("X is broken" refusals persisting for months). Newt's default should stay "save only what a grader can show helps," per the inertness-oracle discipline.
4. **Eight interchangeable memory-provider plugins.** The one-external-at-a-time SPI plus schema-normalization/name-collision/shadowing defenses (`memory_manager.py:49-145,374-434`) is pure surface-area tax. Newt has one settled recall design; keep it.
5. **Unmeasured knobs and doc drift.** `flush_min_turns` documented but unimplemented (`cli-config.yaml.example:549`, no code hits); README sells "LLM-summarized recall" the codebase explicitly removed (`README.md:19` vs `session_search_tool.py:23-30`). Newt's documentation-audit norms should treat this as the cautionary example.
6. **Monolith scale** — 16k/20k-line entry files make every one of the above subsystems reviewable only by grep archaeology; newt's small-crates rule is the counter-position, keep it.

# Newt context/memory/conversation systems — current state

## 1. MemoryProvider trait + MemoryManager (`newt-core/src/memory.rs`)

**Trait methods** (memory.rs:103-180): `name()`, `initialize(&SessionContext)` (default no-op), `system_prompt_block()` — "Called once at session start and **frozen** — mid-session writes to memory must NOT change this return value (keeps the KV/prefix cache valid)" (:113-117), `prefetch(&str)` (default `Ok(String::new())`, :125), `build_messages(system_prompt, new_task) -> Vec<MemMessage>` ("This is where history management lives", :129-138), `sync_turn(user, assistant, &TurnMetrics)` (:144), `reset()` (:149), `restore_turns(&[ConversationTurn])` (default no-op, :157), `on_pre_compress(&[MemMessage]) -> String` (:162), `on_session_end` (:167), `usage() -> Option<(label, current, max)>` (:171), `add_note(&str)` (default `bail!("this memory provider does not support persistent notes")`, :177).

**MemoryManager** (:191-321): registration-order fan-out with fault isolation (init errors only `tracing::warn!`, :210-212). `build_system_prompt_additions()` joins all `system_prompt_block()`s with `\n\n` (:218-224). `build_messages()` uses the **first provider returning non-empty** (:245-257) — so only one history provider is meaningful; system-prompt-only providers (Soul/Agents/NoteStore) return `Vec::new()` from `build_messages` (e.g. :684-687, :1131-1134, agents.rs:153-156). `add_note` routes by **string name match** `p.name() == "note_store"` (:309) because `Box<dyn MemoryProvider>` can't downcast (:312-314). `prefetch_all` exists (:227-239) but **no provider implements `prefetch`** — dead surface.

### Providers

- **RollingWindow** (:337-420, default): keeps last `max_turns` `(user, assistant)` string pairs; config `[memory] window`, default 20 (:363-369). `sync_turn` caps storage at `max_turns*2` (:396-399). Default provider when config absent (newt-tui/src/lib.rs:1316-1318).
- **TokenBudget** (:442-556): prune-oldest-first when `used > max_tokens * threshold` (0.80, default max 8,192; :461-469, :480-488). Token counting: real `metrics.usage` (`input_tokens + output_tokens`) when the backend reports it, **else `(user.len()+assistant.len())/4` chars heuristic** (:507-514). `restore_turns` always re-estimates with chars/4 (:543) — restored histories lose real counts.
- **NoteStore** (:570-698): persistent `~/.newt/NOTES.md`, 2,200-char limit (:580). Read at `initialize`, snapshot **frozen** into system prompt; "Mid-session writes (via `/remember <fact>`) update the file but NOT the system prompt block — changes take effect next session" (:565-567). **Write path: only the human, via `/remember <fact>`** (newt-tui/src/lib.rs:1407-1414, help text :4519). The model has **no note tool and no nudge** to write notes — there is zero agent-initiated memory write. Dedup is exact substring match (:606-608); over-limit add hard-fails (:611-617).
- **Summarizing** (:728-941): triggers when `used_tokens > 0.80 * max_tokens`; summarizes oldest 50% of turns (`compress_ratio: 0.50`, :748) into one `[context summary]` history entry; iterative — prev summary prepended to next prompt (:800-804); anti-thrashing skips when last two compressions saved <10% (:778-784). **Summarization is a real LLM call in the TUI**: `with_summarizer` closure wired in newt-tui/src/lib.rs:1263-1314 — a raw blocking `reqwest` POST to the *current backend* (`/api/chat` or `/v1/chat/completions`), 60s timeout, captures url/model at session start so "model switches mid-session will update on next session restart" (:1266-1267). Without an injected summarizer the fallback is the placeholder string `"[N turns summarised — configure a summariser for real summaries]"` (memory.rs:834-839). On summarizer error, turns are put back and compression aborted (:824-831). Note: `compress_sync` runs **inside `sync_turn`** — the turn loop blocks on the summarization HTTP call, contradicting the trait's "queue writes and return immediately" doc (:142-144). Summary token count is chars/4 (:842).
- **SoulProvider** (:1017-1137): identity resolution explicit `[memory] soul_file` → `.newt/soul.md` (workspace) → `~/.newt/soul.md` → `DEFAULT_SOUL` const (:954-1004, lists the 7 tools, has a regression test that the tool list can't go stale, :1317-1336). Frozen at initialize.

## 2. AgentsProvider (`newt-core/src/agents.rs`)

System-prompt-only provider loading `AGENTS.md` then `CLAUDE.md` from workspace root (or `[agents] path` / `--agents-file` override via `NEWT_AGENTS_FILE`/`NEWT_NO_AGENTS_FILE` env, lib.rs:1251-1256). Per-file cap 65,536 bytes with `[... truncated]` marker (agents.rs:45, :70-78). Frozen at initialize (:129-133). Block header: "Project-specific instructions found in the workspace. Follow them unless they conflict with a direct user request" (:139-143). **No recursive/parent-dir or subdirectory discovery; root only** (single dir scanned, :112-119).

## 3. ConversationStore (`newt-core/src/conversation.rs`)

- **Record schema** (:23-35): `ConversationRecord { id, title, workspace, workspace_id, persona: Option, turns: Vec<ConversationTurn{user, assistant}>, created_at_unix_nanos, updated_at_unix_nanos }` — pretty JSON, one file per conversation at `~/.newt/conversations/<workspace_id>/<id>.json` (:269-275; root from `conversation_root_dir()`, lib.rs:2234-2238).
- **Workspace keying**: yes, **UUIDv5 of canonicalized path** — `Uuid::new_v5(&Uuid::NAMESPACE_URL, normalized_path)` (:70-74). Path-keyed, so a renamed/moved/re-cloned workspace orphans its history (decision doc proposes git-remote keying instead).
- Conversation id = `{unix_nanos}-{uuid_v4}` (:300-302); atomic write-then-rename (:200-215); corrupt records skipped loudly, never poison list/prune (:244-261); prune to `max_per_workspace` oldest-first **on create only**, not on append (:119-127, :217-231); id prefix resolution with ambiguity error (:176-198). Delete also removes the per-session plan dir `.newt/sessions/<id>/` (:161-174, issue #220).
- **Turn granularity: only final `(user, assistant)` text pairs.** `save_successful_conversation_turn` (lib.rs:2268-2285) saves `task` + final `reply`; **all tool calls/results within a turn are discarded** — restore cannot recover what the agent actually did, only what it said.
- **TUI commands** (lib.rs:1993-2030, 2342-2401): `/conversation [list]`, `show <id>`, `restore <id>`, `rename <id> <title>`, `delete|rm <id>`. Restore: `memory.restore_turns(&record.turns)` fans out to all providers (:2354), reloads the saved persona (warning if missing, :2356-2365), adopts the record's id **before** rebuilding the system prompt so the plan file resumes too (:2366-2375). Deleting the active conversation is refused (:2394-2396).
- **NO auto-resume.** Session start always mints a fresh id: `let mut active_conversation_id: String = newt_core::new_conversation_id();` (lib.rs:1175). The decision doc states it flatly: "Invocation #2 in the same folder starts from zero" (conversation_context_architecture.md:40-42).

## 4. TUI in-loop context controls (`newt-tui/src/lib.rs`)

- **Turn flow**: `memory.build_messages(&system, &task)` (:1568) → `chat_complete` (:3571) → on success `memory.sync_all(&task, &reply, &metrics)` (:1615-1617) → `save_successful_conversation_turn` (:1618-1630, failure is a printed warning, non-fatal) → tuning writeback: `record_overflow` if `reply.is_empty()` else `record_success` (:1640-1650).
- **System prompt** (`build_system_prompt_with_persona`, :2046-2136): soul/agents/notes additions + workspace path + persona + per-session plan instruction (`.newt/sessions/<id>/plan.md`, :2068-2075) + skills index (names only, progressive disclosure, :2077-2088) + top-level dir listing (40 entries, hidden excluded, :2091-2109) + README excerpt (3,000 chars, :2112-2122) + `git log --oneline -10` (:2125-2133). Rebuilt only on `/new`, persona swap, or restore — frozen per conversation.
- **Token estimation**: `estimate_tokens` = `chars/4` over JSON serialization, "deliberately cheap (no tokenizer)" (:2680-2694). **No exact tokenizer anywhere.**
- **Mid-loop trim** (`mid_loop_trim`, :2730-2749): fires on message count > threshold (default 40, clamped to `max_tool_rounds - 3` so it always fires before the 25-round cap, :2963-2975) OR estimated tokens > `[tui].mid_loop_trim_tokens` (issue #223). Applied at top of every round (:3669-3687).
- **`trim_for_summary`** (:2655-2678): keeps first `head` (system + original task) and last `tail` messages, inserts a single `"[N earlier tool-call messages omitted…]"` placeholder, then `repair_orphaned_tool_calls` (:2791-2858, two-pass: strips assistant `tool_calls` missing any result; drops orphaned `role:"tool"` messages — prevents Anthropic/Bedrock 400s). **Dropped middle is discarded, not summarized** — despite the function name, no LLM summary of trimmed content occurs; `MemoryManager::on_pre_compress` is never called from the trim path.
- **Pre-send token guard exists** (issue #223): `send_budget = max_ok_input.or(safe_context)` (:3624); `trim_to_token_budget` (:2705-2721, halves the tail each pass) runs before every dispatch (:3692-3706). Plus graceful hard-400 recovery: `recover_context_window_400` parses "prompt is too long: N tokens > M maximum", persists `max_ok_input = 0.8*M` to cache, trims, retries up to 2x (:2759-2768, :3757-3771; probe.rs:156-173).
- **Empty-response overflow retry** (:3873-3896): when probe AND stream are both empty and `input_tokens >= safe_context * 85 / 100`, emits notice and retries up to 2x with aggressive trim `trim_for_summary(&messages, 2, max_tool_rounds/4)` (:3890); otherwise returns "(model returned an empty response — …)" (:3895).
- **Cap exit** (:3955-3968): at `max_tool_rounds`, `trim_for_summary(&messages, 2, 6)` then `final_summary_ollama` — one **tools-disabled** completion ("No `tools` key => the model cannot emit tool calls", :4024) with the nudge "Do NOT call any more tools. Summarize what you found…" (:3981-3987); fallback message includes consumed tokens (:3992-4005).
- **Read-only nudge** (:3646-3664): after 3 consecutive read-only rounds, injects "Stop exploring. Call edit_file or write_file now."
- Parallel `openai_chat_complete` loop at :4158 for OpenAI-wire backends (two loops to maintain).

## LIMITATIONS (each tied to code)

1. **No exact tokenizer** — every estimate is chars/4: `estimate_tokens` (lib.rs:2688-2694), TokenBudget fallback (memory.rs:511-514), Summarizing (memory.rs:892), summary self-count (memory.rs:842), all `restore_turns` re-estimates (memory.rs:543, :916). The 80%/75% safety margins exist to absorb this error (probe.rs:149-153).
2. **No auto-resume / no folder=conversation** — fresh `new_conversation_id()` every launch (lib.rs:1175); resume is manual `/conversation restore <id>`; the fix is only a Proposed decision doc not in ROADMAP numbering.
3. **Tool-round history is never persisted or remembered** — both `sync_all` and the conversation record store only `(task, final_reply)` (lib.rs:1616, 2268-2285); the next turn's `build_messages` has no record of files read/edited last turn beyond what the reply text mentions.
4. **Mid-loop trimming discards, never summarizes** — `trim_for_summary` replaces the middle with a one-line placeholder (lib.rs:2666-2671); `on_pre_compress` hooks (memory.rs:162-164, :281-290) are wired only into `Summarizing`'s own path, never called by the TUI trim/overflow paths.
5. **Summarization quality/robustness** — only active with `[memory] provider = "summarizing"` (default is RollingWindow, config.rs:295); placeholder string if no summarizer (memory.rs:834-839); blocking HTTP inside `sync_turn` violates the non-blocking contract (memory.rs:142-144 vs lib.rs:1290-1305); summarizer pinned to session-start model/url (lib.rs:1266-1267); restore wipes `prev_summary` (memory.rs:919).
6. **No cross-session search** — `/conversation list/show` only (lib.rs:2002-2029); no full-text search, no embeddings/vector store, `prefetch()` unimplemented by every provider (memory.rs:125-127).
7. **Memory write path is human-only** — NOTES.md written solely by `/remember` (lib.rs:1407-1414); no agent tool, no end-of-session extraction (`on_session_end` is a no-op everywhere), 2,200-char cap with hard failure (memory.rs:611-617), exact-substring dedup only (memory.rs:606-608).
8. **Frozen system prompt is stale by design** — notes (memory.rs:565-567), soul, agents files, dir listing, git log (lib.rs:2091-2133) all snapshot at session/conversation start; mid-session repo changes invisible until `/new`.
9. **Workspace keying is path-fragile** — UUIDv5 of canonical path (conversation.rs:70-74); moves/clones/containers lose history (acknowledged in the decision doc :88-94).
10. **TokenBudget/Summarizing budgets are decoupled from probe tuning** — provider `max_tokens` defaults to 8,192 from `[memory] context_tokens` (memory.rs:462-469) and never reads `model-capabilities.json` `safe_context`; two independent budget systems can disagree.
11. **History providers truncate silently** — RollingWindow drops turns past the window with no summary or marker to the model (memory.rs:381); TokenBudget prune likewise (memory.rs:480-488, only `tracing::info!`).
12. **Restored conversations lose persona-unavailable context safely but lose token truth** — restore re-estimates and may immediately re-prune/compress with the chars/4 numbers (memory.rs:537-547, :910-925).
13. **Dual chat loops** — Ollama (lib.rs:3571) vs OpenAI (lib.rs:4158) duplicate trim/overflow logic; ROADMAP 9.7 plans the extraction to `newt-core::agentic` (ROADMAP:552) but it hasn't landed.
14. **`first non-empty wins` build_messages** (memory.rs:245-257) means providers can't compose history (e.g. RollingWindow + retrieval); composition exists only at the system-prompt layer.

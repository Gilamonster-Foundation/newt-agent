# Hermes Agent — Context-Window Management System

## Architecture overview

Pluggable engine pattern. `agent/context_engine.py` defines abstract `ContextEngine` (ABC); the default implementation is `ContextCompressor` in `agent/context_compressor.py` (1,583 lines). Selection is config-driven: "Selection is config-driven: ``context.engine`` in config.yaml. Default is ``\"compressor\"``" (context_engine.py:9-10). Plugin engines load from `plugins/context_engine/<name>/` (run_agent.py:2297-2320). The lifecycle contract (context_engine.py:18-26): instantiate → `on_session_start()` → `update_from_response(usage)` after each API response → `should_compress()` checked per turn → `compress()` when true → `on_session_end()` at real session boundaries only.

Engines MUST maintain public token-state fields read directly by run_agent.py: `last_prompt_tokens`, `last_completion_tokens`, `threshold_tokens`, `context_length`, `compression_count` (context_engine.py:46-51). ABC defaults: `threshold_percent=0.75, protect_first_n=3, protect_last_n=6` (context_engine.py:64-66); the concrete `ContextCompressor` defaults to `threshold_percent=0.50, protect_first_n=3, protect_last_n=20, summary_target_ratio=0.20` (context_compressor.py:404-417), wired from config `compression.{threshold,enabled,target_ratio,protect_last_n,protect_first_n}` (run_agent.py:2130-2153). Per-model threshold override hook: `_compression_threshold_for_model()` returns 0.75 for Arcee Trinity thinking models (auxiliary_client.py:227-239, applied run_agent.py:2134-2141).

## Token accounting — estimates, not a tokenizer

No tiktoken/tokenizer anywhere. Three estimators in `agent/model_metadata.py`:
- `estimate_tokens_rough(text)` — `(len(text) + 3) // 4` ceiling division so 1-3 char strings never count as 0 (model_metadata.py:1717-1726).
- `estimate_messages_tokens_rough(messages)` — chars/4 plus a flat `_IMAGE_TOKEN_COST = 1500` per image part; "Without this, a single ~1MB screenshot would be estimated at ~250K tokens and trigger premature context compression" (model_metadata.py:1729-1743). `_estimate_message_chars` strips base64 image payloads before counting (1772-1802).
- `estimate_request_tokens_rough(messages, system_prompt, tools)` — adds tool schemas: "With 50+ tools enabled, schemas alone can add 20-30K tokens — a significant blind spot when only counting messages" (model_metadata.py:1805-1825).

**Real counts when available:** after each API response `update_from_response()` stores the provider's `prompt_tokens`/`completion_tokens` (context_compressor.py:488-491). The mid-loop check uses ONLY `prompt_tokens` — "completion/reasoning tokens don't consume context window space. Thinking models (GLM-5.1, QwQ, DeepSeek R1) inflate completion_tokens... causing premature compression. (#12026)" (run_agent.py:15316-15323); falls back to the rough estimate when `last_prompt_tokens == 0` (stale after disconnect, #2153, run_agent.py:15311-15331). The compressor's char-budget currency uses `_CHARS_PER_TOKEN = 4` and `_IMAGE_TOKEN_ESTIMATE = 1600` per image ("Matches Claude Code's IMAGE_TOKEN_ESTIMATE constant", context_compressor.py:64-75), with `_content_length_for_budget()` handling multimodal lists (79-109).

**Context length resolution** (`get_model_context_length`, model_metadata.py:1428-1714) is a 10-step waterfall documented in its docstring: config override → persistent on-disk cache (with stale-entry invalidation for Codex OAuth ≥400K and Kimi 32K underreports, 1493-1529) → Bedrock static table → custom-endpoint `/models` probe → Ollama `/api/show` → Anthropic `/v1/models` → provider-aware lookups (Copilot/Nous/Codex/GMI/models.dev) → OpenRouter → hardcoded `DEFAULT_CONTEXT_LENGTHS` (longest-key-first fuzzy match, 1694-1703) → `DEFAULT_FALLBACK_CONTEXT = 256_000` (model_metadata.py:118-128). `MINIMUM_CONTEXT_LENGTH = 64_000` (model_metadata.py:133) floors `threshold_tokens` (context_compressor.py:439-442).

## Trigger conditions — four distinct paths

1. **Pre-send guard (preflight)** — run_agent.py:12372-12431. Before every API call, if `compression_enabled` and message count exceeds `protect_first_n + protect_last_n + 1`, compute `estimate_request_tokens_rough(messages, system_prompt, tools)`; if `>= threshold_tokens`, compress in a loop of **up to 3 passes**, breaking when under threshold or when a pass fails to shrink the list (`len(messages) >= _orig_len`). This is the over-limit prevention guard — it fires "rather than waiting for an API error (which might be caught as a non-retryable 4xx and abort the request entirely)" (12370-12371). Also resets empty-content retry counters post-compression (12414-12420).
2. **Post-response check** — run_agent.py:15302-15339. After each assistant turn with tool calls, `should_compress(_real_tokens)` using the provider-reported `prompt_tokens`. `should_compress()` itself: fire iff `tokens >= threshold_tokens` AND anti-thrashing allows — "if the last two compressions each saved less than 10%, skip compression to avoid infinite loops" (`_ineffective_compression_count >= 2` → False, context_compressor.py:493-513).
3. **Error-driven recovery** — run_agent.py:~14400-14583. `error_classifier.py` classifies context overflow errors (`FailoverReason.context_overflow`, `should_compress=True` flags; substrings "context length", "maximum context" etc., error_classifier.py:43,80,170-189). On overflow: distinguish "input too large" from "max_tokens too large" via `parse_available_output_tokens_from_error` (the latter only caps `_ephemeral_max_output_tokens = available - 64`, never shrinks the window, 14448-14479). For input overflow: `parse_context_limit_from_error()` regex-extracts the real limit from provider error text (model_metadata.py:885-904); else step down `CONTEXT_PROBE_TIERS = [256K,128K,64K,32K,16K,8K]` via `get_next_probe_tier` (model_metadata.py:118-125, 877-882). Parsed limits are persisted to disk cache; guessed tiers are in-memory only — "persisting them pollutes the cache with wrong values" (`_context_probe_persistable`, run_agent.py:14522-14531). Capped at `max_compression_attempts`, then returns `compression_exhausted: True` (14536-14550). A special branch handles Anthropic's 429 "Extra usage is required for long context requests" by reducing to 200K without persisting ("subscription-tier limitation, not a model capability", 14225-14258).
4. **Manual `/compress [focus-topic]`** — gateway/run.py:11090-11199. Preflight guard `has_content_to_compress()` skips the LLM call when the transcript is entirely inside protected head/tail (context_compressor.py:1359-1368). Result feedback via `summarize_manual_compression()` (agent/manual_compression_feedback.py:8-49): reports `before→after` message counts, `~before:,→~after:,` token estimates, noop detection (exact list equality), and a note when fewer messages still cost MORE tokens ("compression rewrites the transcript into denser summaries", lines 38-42). Surfaces summary-failure/dropped-count and broken-aux-model-config warnings (gateway/run.py:11175-11182).

## Compression algorithm (compress(), context_compressor.py:1374-1583)

Order of operations:

**Phase 1 — cheap tool-result pruning, no LLM** (`_prune_old_tool_results`, 519-685). Three passes over messages outside the protected tail (tail determined by token budget walk with `min_protect` count floor, 565-595):
- Pass 1: dedupe identical tool results >200 chars by md5 — older duplicates become `"[Duplicate tool output — same content as a more recent call]"` (597-621).
- Pass 2: replace old tool results >200 chars with informative one-liners from `_summarize_tool_result()` — per-tool templates like `[terminal] ran \`npm test\` -> exit 0, 47 lines output` (224-343); multimodal screenshots stripped to `"[screenshot removed to save context]"` (633-643, fixing "an old computer_use screenshot (~1MB base64 + ~1500 real tokens) survives every compression pass forever").
- Pass 3: shrink tool_call `function.arguments` >500 chars **inside the parsed JSON structure** so the result stays valid JSON — `_truncate_tool_call_args_json` (178-221); naive byte-slicing previously caused MiniMax 400 loops (issue #11762).

**Phase 2 — boundaries.** Head = system prompt (always implicitly protected) + `protect_first_n` non-system messages (`_protect_head_size`, 1188-1206). Tail = `_find_tail_cut_by_tokens` (1292-1353): walk backward accumulating ~tokens until `tail_token_budget` (= `threshold_tokens * summary_target_ratio`, recalibrated on model switch, 392-402), soft ceiling 1.5×, hard minimum 3 messages. Boundary fixups: `_align_boundary_forward` (skip orphan tool results, 1178-1186), `_align_boundary_backward` (never split an assistant+tool_results group, 1208-1230), and `_ensure_last_user_message_in_tail` (1245-1290) — guarantees the most recent user message is never summarized away (bug #10896: otherwise "the task effectively disappears from the active context").

**Phase 3 — LLM summary** (`_generate_summary`, 793-1071) via auxiliary model (`call_llm(task="compression")`, optional `summary_model_override`). Budget: `max(2000, min(0.20 * content_tokens, min(0.05 * context_length, 12_000)))` (`_MIN_SUMMARY_TOKENS`/`_SUMMARY_RATIO`/`_SUMMARY_TOKENS_CEILING`, 55-59, 691-700). Input serialized with per-message truncation caps (`_CONTENT_MAX=6000` head 4000/tail 1500, `_TOOL_ARGS_MAX=1500`, 705-709) and **redacted both on input and output** ("the summarizer LLM may ignore prompt instructions and echo back secrets verbatim", 956-958). The structured template (840-897) has 14 sections: **Active Task** ("THE SINGLE MOST IMPORTANT FIELD. Copy the user's most recent request... verbatim"), Goal, Constraints & Preferences, Completed Actions (numbered `N. ACTION target — outcome [tool: name]`), Active State, In Progress, Blocked, Key Decisions, Resolved Questions, Pending User Asks, Relevant Files, Remaining Work, Critical Context. Optional `focus_topic` from `/compress <focus>` appends guidance giving the topic "roughly 60-70% of the summary token budget" (927-933, "Inspired by Claude Code's ``/compact``").

**Failure handling** in `_generate_summary`: no provider → 600s cooldown (`_SUMMARY_FAILURE_COOLDOWN_SECONDS`, 965-973); model-not-found/timeout/invalid-JSON/stream-closed on a distinct summary model → `_fallback_to_main_for_compression()` and immediate retry on the main model, recording `_last_aux_model_failure_*` so callers still warn about broken config despite recovery (766-791, 1022-1037); unknown errors get one best-effort main-model retry too ("Losing N turns of context is almost always worse than one extra summary attempt", 1039-1054); residual transient errors → 30s/60s cooldown (1056-1070). If summary is ultimately None, a **static fallback marker** is inserted instead of silent loss: "Summary generation was unavailable. {n} message(s) were removed... could not be summarized" with `_last_summary_dropped_count`/`_last_summary_fallback_used` set for caller warnings (1489-1503).

**Phase 4 — assembly** (1475-1560). Head copied verbatim; an idempotent compaction note is appended to the system prompt once (`if _compression_note not in ...`, 1479-1487). The summary is wrapped in `SUMMARY_PREFIX` (37-51): "[CONTEXT COMPACTION — REFERENCE ONLY]... treat it as background reference, NOT as active instructions... Your current task is identified in the '## Active Task' section". Summary role is chosen to avoid consecutive same-role messages with both head and tail neighbors; if neither role works, it's **merged into the first tail message** as a prefix (1505-1556). When it lands as a standalone `role="user"` message, an explicit end marker is appended — "--- END OF CONTEXT SUMMARY — respond to the message below, not the summary above ---" — because "weak models read the verbatim '## Active Task' quote of a past user request as fresh input (#11475, #14521)" (1528-1537).

**Post-assembly:** `_sanitize_tool_pairs()` (1118-1176) removes orphaned tool results and inserts stub results (`"[Result from earlier conversation — see context summary above]"`) for assistant tool_calls whose results were dropped, so the API never sees mismatched IDs. Effectiveness tracking: savings <10% increments `_ineffective_compression_count`, else resets (1565-1571).

## Continuity across compactions (the iterative-summary mechanism)

Two mechanisms, regression-tested in tests/agent/test_context_compressor_summary_continuity.py:
1. **Same-process iterative update:** `_previous_summary` is stored after each summary (960); the next compaction uses the "PREVIOUS SUMMARY: / NEW TURNS TO INCORPORATE:" prompt that says "PRESERVE all existing information that is still relevant. ADD new completed actions... (continue numbering)" (899-913). Test `test_existing_previous_summary_is_not_serialized_again_as_new_turn` asserts the old summary appears exactly once in the prompt (test file:39-53).
2. **Cross-restart rehydration:** `compress()` scans the window for the newest message starting with `SUMMARY_PREFIX` (or `LEGACY_SUMMARY_PREFIX`) via `_find_latest_context_summary` (1093-1105); if found, it strips the prefix, restores `_previous_summary`, and excludes the handoff message itself from `turns_to_summarize` (1439-1448) — so a persisted handoff regains summary identity after resume instead of being double-summarized (test:55-69).

Additionally, `_compress_context` in run_agent.py (10640-10835) rotates the session: memory provider `on_pre_compress` hook (10679-10683), todo-list snapshot re-injected as a user message after compression (10718-10720), old session ended with reason "compression" and a new session_id created with `parent_session_id` lineage (10726-10759), context engine notified with `boundary_reason="compression"` so plugin engines preserve DAG lineage (10765-10779), file-read dedup cache cleared ("if the model re-reads the same file it needs the full content, not a 'file unchanged' stub", 10821-10828), and post-compression token estimate written back to `last_prompt_tokens` including tool schemas (#14695, 10807-10818). Warns the user after ≥2 compressions: "accuracy may degrade. Consider /new" (10798-10805).

## Context references (agent/context_references.py)

Not pinning — **@-mention expansion at message-preprocessing time** (called from cli.py, gateway/run.py, tui_gateway/server.py). `REFERENCE_PATTERN` (17-19) matches `@diff`, `@staged`, `@file:path[:N-M]`, `@folder:path`, `@git:N`, `@url:...` (quoted values and line ranges supported, 381-404). `preprocess_context_references_async` (132-203) expands each ref into a labeled block (`📄 @file:x (N tokens)` fenced code, folder listings via `rg --files`, `git diff`/`log -p`, URL via `web_extract_tool`), strips the tokens from the message, and appends blocks under `--- Attached Context ---`. **Token budgets tied to the model's window:** hard refuse at 50% of `context_length`, warn at 25% (167-186) — `injected_tokens` measured by `estimate_tokens_rough`. Security: paths confined to `allowed_root` (default cwd, 144-149, `_resolve_path` 329-339) and a sensitive-path blocklist (~/.ssh, ~/.aws, ~/.netrc, hermes `.env`, etc., 21-37, 342-360). Interaction with compression is indirect: expanded content lives inside the user message, so it ages through the normal head/middle/tail pipeline like any other turn.

## Prompt-cache friendliness

- `agent/prompt_caching.py` — single `system_and_3` layout: 4 Anthropic `cache_control` breakpoints (system prompt + last 3 non-system messages, same TTL 5m/1h), "Reduces input token costs by ~75% on multi-turn conversations" (1-9, 49-79); applied at run_agent.py:12765.
- Stable-prefix discipline: plugin-injected context goes into the **user message, never the system prompt** — "This preserves the prompt cache prefix — the system prompt stays identical across turns so cached tokens are reused" (run_agent.py:12437-12442).
- The compaction note added to the system prompt is idempotent (substring check, context_compressor.py:1482) so repeated compactions don't keep mutating the cached system block. (Compression itself necessarily invalidates the message-history cache once per compaction.)

## Design ideas worth stealing

1. **Validity-preserving structural pruning before LLM summarization.** The cheap pre-pass (dedupe by hash → per-tool one-line summaries → JSON-aware tool-arg shrinking) reclaims most tokens with zero LLM cost and zero provider-400 risk — `_truncate_tool_call_args_json` parses-shrinks-reserializes instead of byte-slicing (context_compressor.py:178-221), and `_sanitize_tool_pairs` guarantees the post-compression list is API-well-formed by deleting orphan results / stubbing orphan calls (1118-1176).
2. **Iterative summary-of-summary with persisted rehydration.** Keep `_previous_summary` and feed it back as "PREVIOUS SUMMARY / NEW TURNS TO INCORPORATE" with continue-the-numbering instructions (899-913), plus prefix-scanning the transcript so the chain survives process restarts (1439-1448). Prevents the classic lossy-telescope problem where each compaction re-summarizes a summary blindly.
3. **The "Active Task verbatim + last-user-message anchor" pair.** The template's `## Active Task` field copies the user's latest request word-for-word, and `_ensure_last_user_message_in_tail` (1245-1290) structurally guarantees the newest user message is never compressed — belt and suspenders against the agent losing its current task (bugs #10896/#11475/#14521), including the explicit "--- END OF CONTEXT SUMMARY ---" marker for weak models.
4. **Probe-tier context discovery with provenance-gated caching.** When the window is unknown, step down `CONTEXT_PROBE_TIERS` on overflow errors, regex the real limit out of the provider's error text, and persist **only** parsed limits — never guesses, never subscription-tier reductions (`_context_probe_persistable`, run_agent.py:14520-14531; model_metadata.py:877-904). Also the input-overflow vs output-cap-overflow distinction (run_agent.py:14440-14479) avoids needlessly shrinking the window when only `max_tokens` was too big.
5. **Anti-thrashing + effectiveness telemetry.** Measure savings% per compaction; <10% twice in a row disables auto-compression and tells the user to `/new` (context_compressor.py:493-513, 1565-1571), with cooldown timers on summarizer failures (600s no-provider / 60s transient / 30s JSON-decode) and loud-but-recovered warnings when a configured aux model breaks (`_last_aux_model_failure_*`, run_agent.py:10692-10716). Honorable mention: flat per-image token costing (1500-1600 tok/image) on both the estimator and budget sides so base64 screenshots neither trigger premature compaction nor hide from it (model_metadata.py:1729-1743, context_compressor.py:64-75).

# hermes-agent — Session/Conversation Management & Cross-Session Recall

## 1. Session identity model

Two-level identity. A **session_key** (durable, deterministic, derived from message origin) maps to a rotating **session_id** (the transcript). All resets/resumes/handoffs are just re-pointing that mapping.

- `build_session_key()` — `gateway/session.py:600-665`, "the single source of truth for session key construction". Format: `agent:main:{platform}:{chat_type}:{chat_id}[:{thread_id}][:{user_id}]`. Rules: DMs keyed by chat_id (+thread_id); groups append `user_id_alt or user_id` when `group_sessions_per_user=True` (default → per-user isolation in groups); threads are **shared** across participants by default (`thread_sessions_per_user=False`, session.py:659: "In threads, default to shared sessions"). WhatsApp IDs go through `canonical_whatsapp_identifier` to fix JID/LID alias flips (631, 643-647).
- `is_shared_multi_user_session()` (session.py:579) mirrors those rules; when shared, the system prompt says "Multi-user session — messages are prefixed with [sender name]" instead of pinning a user name, explicitly to avoid busting the prompt cache (session.py:299-308).
- `SessionSource` dataclass (session.py:70-156): platform, chat_id/chat_type/chat_name, user_id(+alt), thread_id, guild_id, parent_chat_id, message_id, is_bot.
- session_id format: gateway `f"{now.strftime('%Y%m%d_%H%M%S')}_{uuid4().hex[:8]}"` (session.py:918); CLI uses 6-hex (cli.py:5862-5863).
- `SessionEntry` (session.py:424-576) is the per-key record: token/cost counters, `last_prompt_tokens`, and lifecycle flags `was_auto_reset`/`auto_reset_reason`/`reset_had_activity`, `is_fresh_reset` (#6508), `expiry_finalized`, `suspended` (#7536), `resume_pending`/`resume_reason`/`last_resume_marked_at`.

## 2. Persistence format & location

Dual-write, SQLite-primary:

- **SQLite** `~/.hermes/state.db` (`hermes_state.py:34`, `DEFAULT_DB_PATH = get_hermes_home() / "state.db"`; HERMES_HOME env override, hermes_constants.py:14). Schema v11 (hermes_state.py:36): `sessions` (id, source, user_id, model, model_config, system_prompt, **parent_session_id** chain, started/ended_at, end_reason, message/tool/api counts, token+cost columns, title, **handoff_state/handoff_platform/handoff_error**) and `messages` (role, content, tool_call_id/tool_calls/tool_name, timestamp, finish_reason, reasoning/reasoning_content/reasoning_details, codex_* items) — schema at hermes_state.py:185-251. Reasoning fields are replayed into assistant messages on load so "providers that replay reasoning … receive coherent multi-turn reasoning context" (1723-1750).
- **Legacy JSONL** `~/.hermes/sessions/{session_id}.jsonl` (sessions_dir default gateway/config.py:464). `SessionStore.append_to_transcript` (session.py:1255-1292) writes both; `skip_db=True` when the agent already flushed to SQLite, "preventing the duplicate-write bug (#860)".
- `load_transcript` (session.py:1314-1360) loads both and **prefers whichever source has more messages** — guards against silent truncation when a pre-SQLite session only partially migrated ("the model sees a context of 1-4 messages instead of hundreds", 1342-1358).
- **sessions.json** (key→entry index) written atomically: tempfile + fsync + `atomic_replace` (session.py:721-742).
- NFS resilience: `apply_wal_with_fallback` (hermes_state.py:128-160) catches `"locking protocol"`/`"not authorized"`/`"disk i/o error"` and falls back to `journal_mode=DELETE`; `_last_init_error` is captured so `/resume` errors say *why* the DB is down (`format_session_db_unavailable`, 105-125).
- Write path: `_execute_write` (375-425) uses `BEGIN IMMEDIATE` + up to 15 retries with **random 20-150ms jitter** ("SQLite's built-in busy handler … causes convoy effects"; comment at 317-330), 1s SQLite timeout, PASSIVE WAL checkpoint every 50 writes.
- Schema migration: `_parse_schema_columns` (463-505) executes SCHEMA_SQL into an in-memory SQLite and diffs via `PRAGMA table_info` — "Adding a column to SCHEMA_SQL is all that's needed; the reconciliation loop picks it up automatically."

## 3. Resume / auto-resume semantics

- **Reset policy** per platform+chat_type: modes `none|idle|daily|both` (`_should_reset` session.py:790-832; entry-only variant `_is_session_expired` 752). Sessions with active background processes are never reset/expired/pruned (759, 799, 1066-1079).
- **get_or_create_session** (session.py:856-955) is the per-message gate: `suspended` ⇒ forced fresh session ("hard forced-wipe signal and always wins", 887-891); `resume_pending` ⇒ **return the same entry, same session_id**, transcript reloads intact (889-898); else evaluate policy → on expiry create new session_id with `was_auto_reset` set. The flag is consumed once in `gateway/run.py:7206-7268`: prepends `"[System note: The user's previous session expired due to inactivity…]"` and sends a user-facing "◐ Session automatically reset … Use /resume" notice.
- **Crash/restart recovery (#7536)**: `/stop` → `suspend_session`; drain-timeout → `mark_resume_pending` (session.py:988); on startup without a clean-shutdown marker → `suspend_recently_active(max_age_seconds=120)` (session.py:1094) marks recently-active entries `resume_pending="restart_interrupted"`. A `.restart_failure_counts` file (run.py:3005) escalates 3 consecutive interrupted restarts to `suspended`.
- **Startup auto-continue**: `_schedule_resume_pending_sessions` (run.py:3229-3295) synthesizes an **empty-text `internal=True` MessageEvent** per resume-pending session (reasons in `_AUTO_RESUME_REASONS`, run.py:3225, within freshness window); the `_is_resume_pending` branch (run.py:15634-15661) prepends "[System note: Your previous turn … was interrupted by a gateway restart. The conversation history below is intact. If it contains unfinished tool result(s), process them first…]". The flag is cleared **only after a genuinely successful turn** — `_should_clear_resume_pending_after_turn` (run.py:1123) rejects interrupted/partial/failed results.
- **Explicit reset** (`/new`,`/reset`): `reset_session` (session.py:1130) sets `is_fresh_reset` — separate from `was_auto_reset` precisely so a manual reset doesn't fire the "expired" notice (#6508 comment at 462-469).
- **/resume**: `switch_session(session_key, target_session_id)` (session.py:1182-1235) ends the current DB session (`end_reason="session_switch"`) and `reopen_session(target)` so the old transcript replays next turn. Compression-aware: `resolve_resume_session_id` (hermes_state.py:1621-1684) walks `parent_session_id` descendants to the first one that actually holds message rows (#15000).
- **Per-chat implicit auto-resume**: because sessions.json persists key→id, any new message in the same chat continues the conversation until policy expiry — no explicit resume needed.
- **Expiry watcher** (run.py:4052-4135, every 300s): for expired entries, fires `on_session_finalize` plugin hooks (memory flush), cleans cached agent tool resources, evicts the agent cache entry, sets persisted `expiry_finalized` so finalization survives restarts.
- CLI: `hermes -c` (no arg) → `_resolve_last_session(source)` (hermes_cli/main.py:642-659) = `db.search_sessions(source, limit=1)`, MRU-ordered by computed `last_active = MAX(message timestamp) else started_at` (hermes_state.py:2163-2185; tests tests/hermes_cli/test_resolve_last_session.py assert last_active beats started_at). TUI falls back tui→cli (main.py:1328-1330). `-c "name"`/`--resume X` resolve by exact id → unique LIKE-escaped prefix (`resolve_session_id`, hermes_state.py:941-966, ambiguous ⇒ None) → title (`resolve_session_by_title`, 1062, prefers latest in lineage).
- TUI auto-resume: `session.most_recent` RPC (tui_gateway/server.py:2199-2240), used when `display.tui_auto_resume_recent` is on; deny-lists `tool` source rows rather than allow-listing platforms (comment at 2165-2172).

## 4. "Cross-platform conversation continuity" — what it mechanically is

Not a single live session shared across platforms. Each platform chat has its own session_key. Continuity =

1. **One state.db for every surface** (cli, tui, telegram, discord, …, tagged via `sessions.source`) so search/browse/resume see everything.
2. **CLI→platform handoff**: state machine on the sessions row, `None → "pending" → "running" → ("completed"|"failed")` (tests/hermes_cli/test_session_handoff.py:3-10). CLI `/handoff <platform>` ensures a row exists (stub via `set_session_title` if nothing flushed, cli.py:6019-6033), calls `request_handoff` and poll-blocks ~60s (cli.py:6047-6060). Gateway `_handoff_watcher` (run.py:3834-3882, 2s poll) atomically `claim_handoff`s, then `_process_handoff` (run.py:3884-4030): resolves the destination platform's **home channel**, optionally creates a dedicated thread named `"Hermes — {title}"` (`create_handoff_thread`), computes the destination session_key with the same `build_session_key` rules, `get_or_create_session` + `switch_session(dest_key, cli_session_id)` ("The CLI's transcript becomes the active one for the gateway from this moment on", 3985-3988), evicts the cached agent, and dispatches a synthetic internal turn: `"[Session was just handed off from CLI … Briefly confirm you're working here and summarize what we were working on…]"` (4003-4008). Claim is atomic (second claim returns False — test:104-113); `/handoff` is `cli_only` (test:196-202).
3. **Task-local session env**: `gateway/session_context.py` replaces `os.environ`-based `HERMES_SESSION_*` with `ContextVar`s because "Message A's value was silently overwritten by Message B" under asyncio concurrency (docstring 8-23). `get_session_env` (133-156) uses an `_UNSET` sentinel: explicitly-set (even "") wins; never-set falls back to os.environ for CLI/cron compat.

## 5. memory_monitor.py — not conversation memory

`gateway/memory_monitor.py` is **RSS leak telemetry**, ported from cline/cline#10343 (line 4). A daemon thread logs a grep-friendly `[MEMORY] rss=NMB gc=(g0,g1,g2) threads=N uptime=Ns` line every 5 min (config `logging.memory_monitor`), plus `baseline` and `shutdown` snapshots; `resource.getrusage` first, `psutil` fallback, disables itself if neither works (167-172). Started at gateway/run.py:16826.

## 6. FTS5 search architecture, end to end

**Index** (hermes_state.py:253-306): two FTS5 virtual tables maintained by INSERT/DELETE/UPDATE triggers on `messages`, rowid = messages.id, indexed text = `content || ' ' || tool_name || ' ' || tool_calls` — **raw turns including tool-call payloads** are indexed, not summaries. `messages_fts` (unicode61) + `messages_fts_trigram` (`tokenize='trigram'`) for CJK substring search.

**Query** (`search_messages`, hermes_state.py:1880-2149):
- `_sanitize_fts5_query` (1797-1847): protects balanced `"phrases"` via `\x00Qn\x00` placeholders, strips unmatched special chars, trims dangling AND/OR/NOT, and **auto-quotes dotted/hyphenated tokens** (`chat-send`, `P2.2`, `my-app.config.ts`) so FTS5 doesn't split them.
- Routing: CJK query with ≥3 CJK chars **per token** → trigram MATCH; shorter CJK → per-token escaped LIKE over content/tool_name/tool_calls (#20494); otherwise unicode61 MATCH, `ORDER BY rank`, `snippet(messages_fts, 0, '>>>', '<<<', '...', 40)` (1930-1948).
- Each hit gets ±1 surrounding message of context (200-char previews, multimodal lists collapsed to text, 2083-2143), and full content is dropped from results — "snippet is enough, saves tokens" (2145).

**Tool surface** (`tools/session_search_tool.py`, registered as `session_search`, registry at 598-612):
- Two modes (schema text 550-594): empty query = recent-session browse via `list_sessions_rich` — "Zero LLM cost, instant" (`_list_recent_sessions`, 268-322); keyword = FTS5 → summaries. The schema actively coaches the model: "USE THIS PROACTIVELY when … 'remember when', 'last time'" and "Use OR between keywords — FTS5 defaults to AND".
- Pipeline (325-538): FTS5 with `limit=50`; each hit's session resolved to its **lineage root** (`_resolve_to_parent`, 392-415 — "delegation stores detailed content in child sessions, but the user's conversation is the parent"); current-session lineage excluded; dedupe to top N unique sessions (clamped 1-5, default 3); per session: `get_messages_as_conversation` → `_format_conversation` (tool outputs truncated to 250+250 chars, 87-91) → `_truncate_around_matches` to 100k chars choosing the window that covers the most query-match positions (phrase → 200-char proximity co-occurrence → single terms; 25%-before/75%-after bias, 113-195).
- **LLM summarization of hits**: parallel with `asyncio.Semaphore` bounded by `auxiliary.session_search.max_concurrency` (clamp 1-5, default 3); auxiliary model task `"session_search"`, temp 0.1, 10k max tokens, 3 retries; recap prompt asks for goals/actions/decisions/"specific commands, paths, error messages" in past tense (198-259). If summarization is unavailable, falls back to a raw 500-char preview so "matched sessions aren't silently dropped" (#3409, 520-524). Run via `model_tools._run_async` rather than `asyncio.run`-in-thread to avoid event-loop/client deadlocks (#2681, 476-484). Sessions tagged `HERMES_SESSION_SOURCE=tool` are hidden from search/browse (262-265).

## 7. Session browse / list / delete UX

- `hermes sessions browse`: curses picker with arrow nav, wraparound, ESC/q cancel, and **type-to-filter live search** (printable chars append to filter, backspace edits; hermes_cli/main.py:401-639); numbered-list fallback for non-curses. Label precedence title > preview > id. Tests: tests/hermes_cli/test_session_browse.py (simulated key sequences for both modes).
- Listing backbone `list_sessions_rich` (hermes_state.py:1162-1350): single query with correlated subqueries for preview (first 63 chars of first user message) and last_active; hides child sessions except branch children (`parent.end_reason='branched'`); **compression-tip projection** — a root ended by compression is replaced in the list by its live continuation's id/title/count/last_active while keeping the root's started_at ("one logical conversation = one list entry", 1183-1189); `order_by_last_active=True` computes effective last-active with a **recursive CTE walking compression-continuation edges in SQL** so LIMIT/OFFSET stay efficient (1237-1278).
- `hermes sessions delete` accepts a unique ID prefix with confirm, EOF-safe on non-TTY (tests/hermes_cli/test_sessions_delete.py). `delete_session` (hermes_state.py:2276-2308) **orphans children** (`parent_session_id = NULL`) instead of cascade-deleting and removes on-disk `.json`/`.jsonl`/`request_dump_*` files; `prune_sessions` (2310) only prunes *ended* sessions.

## 8. "Lazy session" — two distinct mechanisms

1. **Lazy agent build (TUI)**: `session.create` (tui_gateway/server.py:2095-2150) returns immediately with `"lazy": True` and a skeleton session dict (`agent: None`, `agent_ready` Event); a 50ms `threading.Timer` kicks `_start_agent_build` (server.py:525-616) — "Classic `hermes` shows the prompt before constructing AIAgent; the TUI used to eagerly build it during session.create, making startup feel blocked on tool discovery/model metadata." Any agent-needing RPC routes through `_sess()` (624-629) which triggers the build and blocks on `_wait_agent`.
2. **Lazy SQLite row creation**: the agent defers `create_session` to the first `run_conversation()` — `self._session_db_created = False  # DB row deferred to run_conversation()` (run_agent.py:1963) and `_ensure_db_session` (run_agent.py:2548-2568) which retries next turn on transient failure. Avoids ghost empty rows from sessions that never get a message.
- `tests/test_lazy_session_regressions.py` covers the #18370 fallout: (a) #20001 — after compression rotates `agent.session_id`, `_finalize_session` must end the agent's *current* id, not the stale `session['session_key']`; (b) `_sync_session_key_after_compress` must run post-`run_conversation`; (c) #19029 — `ValueError` from `set_session_title` clears `pending_title` (non-ValueError keeps it for retry); (d) #18765 — `_normalize_empty_agent_response` surfaces errors when the agent did work but returned null; (e) `finalize_orphaned_compression_sessions` marks >7-day-old ghost continuations whose parent ended with `end_reason='compression'` (empty ghosts handled separately by `prune_empty_ghost_sessions`).

## 9. Design ideas worth stealing

1. **Stable key → rotating id indirection** (gateway/session.py:600 + 1182): reset, resume, branch, and cross-platform handoff are all just re-pointing `session_key → session_id`; transcripts are never destroyed by a reset, only the mapping is dropped — `/resume` can restore anything.
2. **Search-then-summarize recall** (tools/session_search_tool.py): FTS5 finds, lineage-resolution dedupes to user-facing conversations, a cheap auxiliary model produces focused recaps so raw transcripts never enter the main context; plus a zero-cost empty-query "recent sessions" mode and a tool description that teaches the model OR-syntax and proactive triggers.
3. **Three-state interruption model** (session.py:458-492, 973-1128; run.py:3229): `suspended` (hard wipe, from /stop or 3-strike `.restart_failure_counts`) vs `resume_pending` (preserve transcript + synthesize an empty internal turn on startup + reason-aware system note) vs policy reset — and the flag clears only on a verified-successful turn (run.py:1123).
4. **Trigger-maintained dual FTS index over content+tool_name+tool_calls** (hermes_state.py:253-306) with unicode61/trigram/LIKE routing by CJK token length — tool activity is recallable, CJK works, and a sanitizer auto-quotes `chat-send`/`P2.2`-style tokens that tokenizers mangle.
5. **Compression lineage as a first-class graph**: `parent_session_id` chains + `end_reason='compression'`, tip-projection in list UIs (recursive CTE for MRU ordering), `resolve_resume_session_id` redirecting resume to where messages actually live, and child→root resolution in search — one logical conversation survives any number of context compressions.
6. Honorable mentions: jittered app-level SQLite write retry + WAL→DELETE NFS fallback with captured init-cause in user errors (hermes_state.py:128-160, 317-446); `load_transcript` "prefer the longer source" migration guard (session.py:1341-1358); ContextVar session env with `_UNSET` sentinel (session_context.py:42-156).

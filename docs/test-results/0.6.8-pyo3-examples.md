# 0.6.8 baseline — PyO3 examples under context overflow

**Version:** 0.6.8 · **Date:** 2026-06-14 · **Experiment:** the "one Python
example per PyO3 crate" task on an **8-crate (~20k-token) overflow corpus** —
see [methodology](../methodology/). **Outcomes:** ✅ pass · ❌ fabricated · ◐
vacuous (wrote `.py`, no imports) · ∅ no-output · ⚠ timeout/error.

## Headline — the dominant barrier is the tool-call protocol, not fabrication

The result we expected (nemotron fabricates the API surface) is confirmed, but
the **bigger** finding is upstream of it: **most local models never complete the
task because of how they do — or don't — tool-call in newt's agentic loop**, not
because they fabricate. On the gnuc 4060 Ti, only 5 of 19 models even produced
imports to judge. The "no-output" majority decomposes into distinct,
**mostly-fixable harness gaps** (see the breakdown below). This reframes 0.6.9:
the first lever is the tool-call layer, *then* nemotron-family fabrication.

### DGX-specific signals

- **The qwen *generation* fixed its tool-call format.** `qwen2.5-coder:*` are ∅ no-output (JSON-in-content newt drops), but `qwen3-coder:30b` ✅ and `qwen3.6:*` ✅ emit **structured `tool_calls`** newt reads. The blocked qwen2.5-coder family is the strongest case for the JSON-in-content parser (0.6.9 #1) — newer qwens already moved on.
- **Coder-tuning matters within a family.** `qwen3:30b` (base) **fabricates**; `qwen3-coder:30b` (coder) **passes** — same generation, same size.
- **`gemma4:26b`: engaged-but-unproductive.** 25 tool events, hit the cap, wrote zero files — a *different* no-output than the no-tool models (it tried, looped, produced nothing). A candidate for the decomposition/anti-loop help.

## Variance — single-run cells are *indicative, not reliable*

Two cells flipped between otherwise-identical conditions, on **opposite axes**:

| model | run A | run B | what changed |
|---|---|---|---|
| `nemotron3:33b` | ❌ FAIL 0/5 (cross-family run, DGX) | ✅ PASS 15/15 (this survey, DGX) | **only the run** — same model, corpus, endpoint |
| `gemma4:e4b` | ✅ PASS 7/7 (gnuc) | ❌ FAIL 0/8 (DGX) | run **and/or** hardware |

So the pass/fail outcome is **stochastic** for borderline models — a single run can mislabel one. Read every cell here as *indicative of a tendency*, not a verdict. The fix is **per-cell repeats → a pass-rate** (the priority survey upgrade), and it sharpens the headline: nemotron doesn't *always* fabricate — it fabricates *at some rate* we can't quantify from N=1.

## Reading the result

- **The tool-call layer gates everything, on both targets.** Across 43 cells,
  most no-output is tool-call: no Ollama tool support (the reasoners, codestral,
  deepseek, gemma3, glm4, llama2) or a JSON-in-content dialect newt drops (the
  `qwen2.5-coder` family, llama3.1). These models never reach the fabrication
  question — the protocol is the gate.
- **Engaging models split by family — but borderline.** Clear passes:
  `devstral-small-2:24b`, `gemma4:e2b`, `qwen3-coder:30b`, `qwen3.6:27b/35b`,
  `nemotron-3-nano:30b`. Clear fabricators: base `qwen3:30b`, `gemma4:e4b` (DGX).
  The **nemotron** family is *borderline*, not uniformly bad — it fabricated in
  the cross-family run but passed `nemotron3:33b` + `nemotron-3-nano:30b` here
  (see Variance). Consistent-with-caveat with the
  [cross-family finding](../findings/2026-06-14-cross-family-confabulation.md).
- **Engaging-but-unproductive is its own failure.** `gemma4:26b` (DGX) and
  `gemma4:e4b` (gnuc) hit the 25-round cap; one wrote nothing, one fabricated.
  Round-cap exhaustion is a distinct candidate for decomposition/anti-loop help.

## 0.6.9 targets (reframed by this baseline)

0. **Per-cell repeats → pass-rate** (priority, from Variance) — single runs
   mislabel borderline models; the matrix needs K runs/cell, not N=1.
1. **Parse JSON-in-content tool calls** — unlock the `qwen2.5-coder` family +
   llama3.1 (the largest blocked group, and they're *trying*; newer qwens already
   emit structured `tool_calls`).
2. **Non-tool whole-file fallback** for models with no Ollama tool support.
3. **Fix the session-plan-file UX trap** (mistral-small loop) + the round-cap
   loop (gemma4:26b engaged 25 rounds, produced nothing).
4. **Nemotron-family fabrication** — decomposition / curated context / verify gate
   so the working set fits and fabrications are caught (and measured as a *rate*).

We may not get every model passing; the line is the **nemotron family green**,
with the tool-call fixes as the prerequisite that lets most others even start.

## Caveats

**Single run per cell** — and the [Variance](#variance--single-run-cells-are-indicative-not-reliable)
section shows that is *not* reliable for borderline models (two cells flipped).
Treat cells as indicative; repeats are the priority fix. Also: module-level
scoring (#74 adds symbol-level); forensics unrecorded for a few fast runs (score
still valid); timeouts/OOM are hardware-bound (a model blocked on the 4060 Ti may
differ on the DGX Spark, and vice-versa).

## 1. Questions + forms

### 1.1 The typed core: `newt_core::Question<A>` / `Action<A>`

- Definition: newt-core/src/tty/widgets/question.rs:3-19 (`Action<A>`: `value: A`, `key: String`, `label: String`, `aliases: Vec<String>`), :41-47 (`Question<A>`: `markdown: String`, `actions: Vec<Action<A>>`, `note: Option<String>`).
- Serde shape: plain field names, no rename/tag. Exactly two attrs: `Action.aliases` has `#[serde(default, skip_serializing_if = "Vec::is_empty")]` (question.rs:17) — `default` keeps pre-aliases persisted forms deserializable, `skip_serializing_if` keeps web/DB JSON byte-identical when empty, both load-bearing per the comment at :8-16; `Question.note` has `#[serde(default, skip_serializing_if = "Option::is_none")]` (question.rs:45). `aliases` is a *data field* (hidden input aliases), not a serde `alias` — there are no `#[serde(alias)]`s anywhere in this family.
- `Question::parse` (question.rs:63-80): deterministic, fail-closed authorization parser. Trims input; canonical match (action `key` OR wire `value.as_ref()`) beats hidden aliases; >1 match at either tier → `None` (deny). Case-sensitive by design (permission menu uses a/A, d/D — :8-14).
- `Question::terminal_text` (question.rs:84-96): brackets the key inside the label via `replacen(key, "[key]", 1)`, joins actions with three spaces, joins markdown/note/choices with `\n`, skipping empties. Aliases never rendered.
- `Action::new` question.rs:22; `with_aliases` question.rs:35.
- Re-export chain: newt-core/src/tty/widgets/mod.rs:31 → newt-core/src/tty/mod.rs:62 → newt-core/src/lib.rs:252 (`pub use tty::{Action, Question}`).

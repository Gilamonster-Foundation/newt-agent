How Newt grants and enforces authority

Every tool call runs under a capability: what it may read, write, run, and reach. The operator sets the ceiling, the gate checks each call, and the kernel enforces it where the OS allows. Step through one write that is allowed and one network call that is not.

Example paths and hosts are illustrative. Types come from newt-core/src/caveats.rs and newt-core/src/agentic/permissions.rs. Keys: left/right arrows step, space plays or pauses.

What this does not show

  • On macOS, deny-all network is supported for audited launches by an unprivileged caller with pipe or null stdio. Hostname-scoped and deputy-relayed network grants are not enforceable there and are refused, so a per-host network fence is not shown.
  • Windows AppContainer does not enforce a restricted exec allowlist; it fails closed and refuses the shell tool.
  • --yolo turns all three off: approvals (--disable-ocap), confinement (--full-access) and the environment (--ambient: your login shell and full environment). Each flag alone changes only its own axis.
  • Signatures do not stop an older valid file being restored, and do not help if an attacker holds the operator key.
  • Open deviations are tracked in docs/security/ocap-deviations.md.
